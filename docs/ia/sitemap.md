**Проверка правил дерева.**
- Корень один — `home`.
- Глубина — 2 уровня при допустимых трёх: вложены только записи в свои архивы (`collection`, `digest-issue`, `review`) и `suggest-thanks` в `suggest`.
- MECE: каждая страница стоит в одном месте, вместе строки закрывают все 20 страниц инвентаря. Страница ресурса стоит на первом уровне, потому что её адрес `/resource/{slug}/` не зависит от раздела. Хлебные крошки при этом ведут через раздел её типа: `Главная › Инструменты › Figma` (раздел «Навигация»).
- Грейд — фильтр внутри архивов `/tools/?level=junior` и `/learn/?level=junior`, а не раздел: отдельной посадочной «для junior» в ТЗ нет (open-questions).
- Имена — латиница kebab-case и совпадают с `pages-inventory.md`.

## Фильтры в URL

Фаза 1.5, утверждена 11.09.2026.

**Правила.**
- Имя параметра — латиницей и равно имени поля или таксономии brief §5.1; значение — латинский ключ (OQ-11).
- Разные оси сочетаются по «И», значения внутри одной оси — по «ИЛИ» без дублей (US-05, US-08, US-11).
- Несколько значений одной оси — через запятую `?platforms=web,mac`, одинаково с JavaScript и без (OQ-12, решает этап 14).
- Канонический адрес любой выборки — архив без параметров, например `/tools/` (US-16). Пустая выдача отвечает 200 с `noindex` (US-16, US-21). Это требование к этапам 14 и 17.
- Пагинация сохраняет параметры: `/tools/page/2/?pricing=free` (US-20).
- Неизвестный параметр или значение не ломает страницу: игнорируется, чипс для него не показывается. Рекомендация для этапа 14.
- Имена параметров не совпадают с зарезервированными query vars WordPress. Проверено 11.09.2026 по `$wp->public_query_vars` локального сайта: `s`, `search`, `name`, `page`, `paged`, `author`, `order`, `orderby`, `tag`, `taxonomy`, `term`, `post_type`, `post_format`, `feed`, `preview`, `robots`, `sitemap`, `embed`, `error` и другие — ни одно имя ниже в этот список не входит.

## Требования к 12

1. Post type `resource`: `rewrite.slug = 'resource'`, `with_front = false`, `has_archive = false`; `/resource/` → 404.
2. Таксономия `resource_type`: корневые адреса `/tools/`, `/learn/`, `/assets/`, `/community/` и их пагинация правилами с приоритетом `top`; фильтр `term_link`; 301 с `/resource_type/{term}/`.
3. Таксономия `topic`: `hierarchical = true`, `rewrite = ['slug' => 'topic', 'hierarchical' => false]`; термы со слагами из раздела «Фильтры в URL».
4. Таксономии `level` и `skill` без публичных архивов; `level` — параметр фильтра в разделах, `skill` — редактор и REST.
5. Подборки, дайджест, обзоры: адреса `/collections/`, `/digest/`, `/reviews/` и `/{раздел}/{slug}/` по OQ-02 а); у записи ровно одна из трёх категорий; 301 с `/category/*`.
6. Поиск на `/search/?s=` по OQ-01 а): правило, пагинация, адрес формы, `search_link`, 301 с `/?s=`.
7. Мета-параметры фильтров как query vars с латинскими ключами (OQ-11); `meta_query` — проба на SQLite до логики; синтаксис нескольких значений — вместе с этапом 14 (OQ-12).
8. Редиректы 301: `/author/*` → `/about/`, `/category/*`, `/resource_type/*`, `/?s=`, `/?topic=`.
9. Ответ 404: `/resource/`, архивы дат, `/tag/*`, `/level/*`, `/skill/*`, номер страницы за пределами.
10. Страница политики получает слаг `privacy`; демо-записи `hello-world` и `sample-page` удаляются.
11. Все правила проверяются `curl` из колонки «Проба»; после регистрации — `wp rewrite flush` и запуск WP-CLI с аргументом, который начинается с `/`, только с `MSYS_NO_PATHCONV=1` или из Python, а не из Git Bash напрямую.

**Заодно для 14 и 17.**
- Канонический адрес выборки с фильтрами — архив без параметров.
- `noindex` получают пустая выдача фильтров, пустая тема, поиск, `suggest-thanks` и `styleguide`.
- `rel="prev"` и `rel="next"` на пагинации.
- `BreadcrumbList` на внутренних страницах.
- Расхождение директивы 17 и ТЗ по индексации фильтра с одним параметром — OQ-13.
