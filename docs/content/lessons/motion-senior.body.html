Пример для всего урока. Магазин кофе из уроков Junior и Middle вырос: над приложением и сайтом работают три дизайнера и две команды разработки. Набор длительностей у каждого свой, про «уменьшить движение» помнят не все, а спор «сделайте поживее» повторяется каждую неделю. Соберём правила движения так, чтобы новый дизайнер мог работать по ним без автора.

1Что анимируем, а что нет

Правила начинаются не с чисел, а со списка изменений, которые бывают в продукте, и решения по каждому.

Анимируют не элементы, а изменения. Шторка — это «крупный элемент появляется поверх экрана», строка корзины — «элемент уходит из списка». Изменений в продукте немного, и для каждого решение принимается один раз:

2Длительности и кривые в токенах

Числа движения живут в одном месте, одинаково в макете и в коде, и называются по роли.

Устройство то же, что у цвета: два слоя. Базовые значения — просто числа с порядковыми именами. Роли — имена, которыми пользуются компоненты. Компонент берёт роль, а не число. Когда меняется значение, правка идёт в одном месте.

Токены движения · CSS
:root {
  /* базовые значения: только внутри системы */
  --duration-100: 100ms;
  --duration-200: 200ms;
  --duration-300: 300ms;
  --duration-400: 400ms;

  /* роли: ими пользуются компоненты */
  --duration-fast: var(--duration-100);
  --duration-short: var(--duration-200);
  --duration-medium: var(--duration-300);
  --duration-long: var(--duration-400);

  --ease-enter: cubic-bezier(0, 0, 0, 1);
  --ease-exit: cubic-bezier(0.3, 0, 1, 1);
  --ease-move: cubic-bezier(0.2, 0, 0, 1);
}

/* компонент берёт роли, а не числа */
.sheet {
  transition: transform var(--duration-medium) var(--ease-enter);
}
.sheet.is-closing {
  transition: transform var(--duration-short) var(--ease-exit);
}
Имена ролей — договорённость команды. Главное, чтобы в макете и в коде они были одни и те же.

Для обмена между макетом и кодом есть формат дизайн-токенов W3C. В нём у длительности и у кривой свои типы:

Токены движения · формат W3C
{
  "duration": {
    "short": { "$type": "duration", "$value": { "value": 200, "unit": "ms" } },
    "medium": { "$type": "duration", "$value": { "value": 300, "unit": "ms" } }
  },
  "ease": {
    "enter": { "$type": "cubicBezier", "$value": [0, 0, 0, 1] },
    "exit": { "$type": "cubicBezier", "$value": [0.3, 0, 1, 1] }
  }
}
Сокращено до двух длительностей и двух кривых. Остальные записываются так же.

В макете роли становятся переменными библиотеки или хотя бы страницей с таблицей, на которую ссылается каждый прототип. Прототип, где длительность вписана руками, при ревью отправляется назад так же, как цвет не из палитры.

Правила движения этого сайта, для примера, умещаются в три значения: 150 мс для смены цвета при наведении, 200 мс для шторки фильтров и одна кривая cubic-bezier(0.2, 0, 0, 1). Все три — токены в одном файле темы. При «уменьшить движение» переходы сокращаются почти до нуля: ни один из них не несёт смысла, который без движения потеряется.

Компонент берёт роль, а не число. Число в прототипе или в коде без имени роли — такая же ошибка, как цвет не из палитры.

3«Добавим, чтобы было живее»

На просьбу добавить движение отвечают не вкусом, а тремя вопросами.

  1. Что оно объясняет? Какое изменение станет понятнее. «Будет живее» — не изменение.
  2. Как часто его увидят? Раз в жизни, раз в день или сорок раз за визит.
  3. Сколько оно стоит? Время человека, плавность на слабом телефоне, люди с настройкой «уменьшить движение».

Ответ бывает не только «да» и «нет». Чаще всего просьба разумная, а параметры надо привести к правилам.

Тренажёр · что ответить на просьбувопрос 1 из 8 · 0 верно

  1. «Пусть логотип на заставке крутится две секунды, это наш бренд».

    ОтклонитьНичего не объясняет, а видят при каждом запуске: каждое открытие начинается с двух секунд ожидания. Бренду место в промо и в первом запуске.

  2. «Шторка фильтров пусть выезжает снизу, а не появляется разом».

    ПринятьЭто строка «крупный элемент поверх»: средне · появление, уход — коротко · уход, при «уменьшить движение» — проявление.

  3. «Кнопка „Оформить“ пусть пульсирует, чтобы на неё чаще нажимали».

    ОтклонитьДвижение без изменения. Оно отвлекает от чтения, а бесконечное движение к тому же надо уметь остановить. Заметность кнопки решается размером, цветом и местом.

  4. «Переход между экранами сделаем 700 мс с размытием фона, так дороже выглядит».

    Принять с правкойСмена экрана по правилам движется, но это «долго», 400 мс, и без размытия: размытие перерисовывается на каждом кадре и дёргается на слабых телефонах.

  5. «Когда статус заказа меняется на „В пути“, пусть новое слово проявляется».

    ПринятьДанные обновились сами, человек мог не заметить. Строка «данные обновились сами»: коротко · появление.

  6. «Карточки товаров пусть въезжают по одной при прокрутке каталога».

    ОтклонитьКаталог листают постоянно. Каждая карточка приходит с задержкой, и ничего нового это не объясняет.

  7. «Удалённый товар пусть улетает с вращением в значок корзины».

    Принять с правкойПоказать удаление правильно, но по строке «элемент уходит из списка»: уход и смыкание соседей, без вращения и полёта через экран.

  8. «После первого заказа покажем конфетти».

    Принять с правкойУкрашение в редкий момент допустимо: один раз, до секунды, не мешает нажать дальше. При «уменьшить движение» не показывается.

Каждый ответ — ссылка на строку таблицы из раздела 1. Если строки не нашлось, это повод обсудить правила, а не решить по месту.

4Производительность: проверка и отказ

Анимация, которая дёргается на половине телефонов, хуже анимации, которой нет.

Плавным движение выглядит при 60 кадрах в секунду, а это около 16 мс на кадр. В это время браузер должен уложить и работу страницы, и отрисовку. Поэтому правила фиксируют не только что анимируем, но и чем:

  • Двигаем сдвигом, масштабом и прозрачностью. Их браузер меняет почти даром. Ширина, высота и положение от края заставляют пересчитывать раскладку страницы на каждом кадре.
  • Не анимируем тень и размытие. Если без тени никак, анимируется прозрачность слоя, на котором она нарисована.
  • Не двигаем десятки элементов сразу. Сорок строк, въезжающих одна за другой, — это сорок анимаций.
  • Записываем эталонный слабый телефон. Конкретную модель, самую слабую из тех, что поддерживает продукт. Анимация проверяется на нём, а не на ноутбуке дизайнера.
Проверка перед выпускомКакПроходит, если
СвойстваРазработка называет, что меняется во время анимацииТолько сдвиг, масштаб, поворот, прозрачность
Эталонный телефонПройти сценарий на нёмРывков не видно, ввод не ждёт анимацию

Дорогая анимация не попадает в продукт, как бы хорошо она ни выглядела в прототипе. Её упрощают — проявление вместо масштаба, сдвиг вместо высоты — или убирают.

5Когда правила меняются

Правила стареют вместе с продуктом: появляется новый тип изменения, и его вписывают в правила, а не решают по месту.

В приложении магазина появилась сортировка корзины перетаскиванием. Такого изменения в таблице нет: элемент двигается не сам, его ведёт палец. Вот как оно попадает в правила:

  1. Описать изменение. Строку корзины тянут пальцем, соседи расступаются. Бывает редко, по инициативе человека.
  2. Поискать строку в таблице. «Мелкое изменение на месте» и «элемент уходит из списка» близко, но не то: здесь движение без длительности, оно идёт за пальцем.
  3. Предложить новую строку. Пока палец на экране, строка движется за ним без анимации. Соседи расступаются: коротко · перемещение. Отпустили — строка встаёт на место: коротко · перемещение. При «уменьшить движение» строка по-прежнему идёт за пальцем, соседи меняются местами сразу.
  4. Показать и согласовать. Прототип на двух экранах и проба в коде. Разработка подтверждает, что двигаются только сдвигом.
  5. Внести с датой и причиной в журнал изменений правил. Места, где уже сделали по-своему, привести к правилу.
ДатаЧто изменилосьПочему
12.03Новая строка «элемент тянут пальцем»Появилась сортировка корзины перетаскиванием
02.02«Долго» 500 → 400 мсСмена экрана на слабом телефоне ощущалась медленной
15.01Автоматическое движение — только по нажатиюБаннеры на главной мешали читать каталог
Новое число в наборе — последний вариант, а не первый. Сначала ищут подходящую строку, потом новую строку на старых токенах, и только потом новый токен.

6Прогон чужой спецификации

Правила работают, когда по ним можно проверить чужую работу и сослаться на строку, а не на вкус.

Дизайнер соседней команды прислал спецификацию анимаций для нового раздела «Подписка на кофе». Сверьте её с правилами магазина из раздела 1. Пять строк нарушают правила, три в порядке. Нажимайте на строки с нарушением.

  1. Карточка тарифа увеличивается, 250 мс, ease.Нарушение. Выбор — это отклик на нажатие: по правилам только цвет, «быстро». К тому же 250 мс и ease не из набора. Выбранная карточка отличается рамкой и подложкой.
  2. Шторка «Частота доставки».В порядке. Строка «крупный элемент поверх» слово в слово, включая уход и «уменьшить движение».
  3. Число подпрыгивает, пружина, 600 мс.Нарушение. Мелкое изменение на месте: «быстро · перемещение». Пружины в наборе нет, 600 мс втрое дольше «коротко», а поведение при «уменьшить движение» не описано.
  4. Баннер листается сам.Нарушение. Автоматическое движение по правилам — только по нажатию. По WCAG то, что двигается само дольше пяти секунд рядом с другим содержимым, человек должен иметь возможность остановить, а баннер крутится, пока открыт раздел.
  5. Переход к оформлению.В порядке. Смена экрана вперёд: «долго · перемещение», растворение при «уменьшить движение».
  6. Статус «Подписка активна».В порядке. Строка «данные обновились сами».
  7. Зёрна плывут при прокрутке.Нарушение. Украшение в рабочем разделе, да ещё параллакс: WCAG приводит его как пример движения, без которого обычно можно обойтись, а людям с вестибулярными нарушениями от него бывает плохо. По правилам украшения только в промо и один раз.
  8. Кнопка сжимается в круг и крутится, 500 мс.Нарушение. Анимация ширины пересчитывает раскладку на каждом кадре — дорого. 500 мс не из набора. Загрузка по правилам — индикатор: кнопка сохраняет размер, подпись сменяется индикатором.

Замечание к чужой анимации начинается со ссылки на правило. Если сослаться не на что, это либо вкус, либо дыра в правилах. Дыру закрывают новой строкой.

7Задание

Опишите правила движения продукта на одной-двух страницах: что анимируем, какими параметрами, что делаем при «уменьшить движение». Прогоните по ним один чужой макет.

Часть 1 · Инвентаризация, 30 минут

  1. Пройдите основные сценарии продукта и выпишите все изменения: что появляется, уходит, меняется.
  2. Сведите их к типам: отклик на нажатие, элемент поверх, уход из списка, смена экрана и так далее.
  3. Соберите все длительности и кривые, которые сейчас есть в макетах и в коде.

Часть 2 · Правила, 60 минут

  1. Заполните таблицу: изменение, движение, токены, поведение при «уменьшить движение».
  2. Опишите токены в двух слоях — базовые значения и роли — и где они живут в макете и в коде.
  3. Запишите проверку производительности и эталонный слабый телефон.
  4. Опишите, как добавляется новое: кто предлагает, кто согласует, куда пишется.

Часть 3 · Прогон, 30 минут

  1. Возьмите чужой макет или прототип с анимациями: коллеги, соседней команды, прошлого релиза.
  2. Сверьте каждую анимацию с правилами и выпишите расхождения со ссылкой на строку.
  3. Если сослаться не на что, отметьте это как дыру в правилах и допишите строку.

ПРОГОН: ______________________ (чей макет)
расхождение — строка правил — что исправить
______________________ — ___ — ______________________
Документ на одну-две страницы. Если он длиннее, в нём, скорее всего, описаны элементы, а не изменения.
Как понять, что задание выполнено. Спор об анимации в команде закрыт ссылкой на правило.

Что должно получиться

  • Правила движения на одну-две страницы.
  • Токены в двух слоях с одинаковыми именами в макете и в коде.
  • Прогон чужого макета: расхождения со ссылками на строки и дописанные строки, если нашлись дыры.

План работы: 30 минут на инвентаризацию, 60 на правила, 30 на прогон. Всего — около двух часов.

Частые сложности

  • «Правила сковывают бренд». Бренд живёт в промо, в первом запуске, в пустых экранах. В рабочих сценариях движение служит делу, и там правила нужнее всего.
  • «Разработка уже сделала по-своему». Приводите к правилам по частоте: сначала экраны, где человек бывает чаще всего. Остальное — при следующей правке.
  • «У iOS и Android своё движение». Изменения и роли общие, значения платформа может подстроить под себя. В таблице это отдельная колонка, а не отдельные правила.
  • «Документ никто не читает». Правила должны жить там, где работают: токены — в библиотеке макетов и в коде, ссылка на строку — в замечаниях к ревью.

8Чек-лист и ошибки

Правила движения работают, если

  • Описаны изменения, а не элементы
  • По каждому изменению есть движение, токены и поведение при «уменьшить движение»
  • Автоматическое движение — только по нажатию
  • Токены в двух слоях, имена одинаковые в макете и в коде
  • Компоненты берут роли, а не числа
  • Записаны проверка производительности и эталонный слабый телефон
  • Есть порядок добавления нового и журнал изменений
  • Замечание к чужой анимации можно сослать на строку

Что мешает

  • Правила про элементы. «Шторка — 300 мс» вместо «крупный элемент поверх», и каждый новый элемент требует новой строки.
  • Числа без ролей. В коде 300, в макете 280, а смысл знает только автор.
  • «Уменьшить движение» потом. Строки без этой колонки, и решение принимается в коде.
  • Правила без проверки. Анимация дёргается на слабом телефоне, и это выясняется после выпуска.
  • Правила без хозяина. Новое решают по месту, и через полгода таблица не совпадает с продуктом.

9Три ступени темы

Это последняя ступень темы: движение перестаёт быть личным вкусом и становится частью системы.

СтупеньЧто нужно уметьКак проверить результат
Junior Отличать переход, который объясняет, от украшения; подбирать длительность под размер; выбирать кривую; не анимировать частое; описывать анимацию для разработки Для каждого перехода можно назвать, что он помогает понять, переходов «для красоты» не осталось
Middle Показывать движением, откуда появилось и куда исчезло; брать длительности и кривые из общего набора; учитывать «уменьшить движение»; помнить про медленную сеть и слабые телефоны При включённой системной настройке интерфейс остаётся полностью работающим и понятным без движения
Senior — этот урок Описать правила движения продукта: что анимируем и зачем, токены длительностей и кривых, что при «уменьшить движение», как проверяем производительность Спор об анимации в команде закрыт ссылкой на правило
Ориентир по этой теме: любое движение в продукте можно объяснить строкой правил, а новое попадает в продукт через правила, а не мимо них.
