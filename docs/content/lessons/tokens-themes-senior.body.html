1Где живут значения

Значение токена хранится в одном месте. Все остальные места получают копию из него, а не правят своё.

У «Лесной обжарки» токены жили в трёх местах: в переменных Figma, в CSS сайта и в коде приложения.

Каждое место правили отдельно. Через год вторичный текст в Figma — 5B6570, на сайте — 6B7580, в приложении — третий серый.

Никто не ошибся нарочно: правка в одном месте не доходила до двух других.

Два способа выбрать источник

  • Источник — Figma. Значения правят в переменных, а код получает выгрузку. Удобно, когда систему ведут дизайнеры.
  • Источник — репозиторий. Значения лежат в файле токенов рядом с кодом. Код собирается из него, а в Figma файл импортируют. Удобно, когда у токенов много платформ и нужна история правок.

Главное — чтобы источник был один. Правка вне источника считается ошибкой, даже если значение верное.

Выгрузка и загрузка есть и в самой Figma, без плагинов. В окне переменных можно импортировать JSON в формате W3C Design Tokens Community Group — каждый файл становится режимом. И выгрузить в JSON один режим или все режимы коллекции.

Формат этой группы стал стабильным в октябре 2025 года, версия 2025.10. Это не стандарт W3C, а отчёт сообщества, но его уже читает Figma. Инструменты сборки переходят на него: Style Dictionary понимает формат группы с четвёртой версии, а версию 2025.10 — пока не полностью.

Здесь источники расходятся. Андреас Кучман в статье на сайте Мартина Фаулера называет лучшей практикой репозиторий, а не дизайн-инструмент. В «Лукоморье» токены правят в Figma через Tokens Studio и пишут, что выбрали бы так снова. Урок не выбирает за вас: выбирайте по тому, кто чаще правит значения.

У значения один источник. Остальные места получают копию. Способ передачи выбирают один раз и не меняют каждый месяц.

2Одно имя на всех платформах

Имя токена в макете и в коде одно и то же. Меняется только запись — по правилу, которое записано один раз.

В Figma группы разделяет косая черта. В CSS она не годится, в Swift и Kotlin имена пишут слитно.

Поэтому договариваются об одном имени и правиле перевода. Запись на каждой платформе своя.

Например:

  • Figma: color/bg/surface
  • CSS: --color-bg-surface
  • Swift и Kotlin: colorBgSurface

Это одно имя, а не три. Расхождение — когда отличаются слова: color/bg/surface в макете и --card-background в коде.

Как это записать

В файле токенов имя — это путь по группам. Значение роли — ссылка на примитив в фигурных скобках.

Один токен · файл токенов и CSS
tokens/roles.light.tokens.json
{
  "color": {
    "bg": {
      "surface": {
        "$type": "color",
        "$value": "{gray.0}",
        "$description": "Карточки, шапка, нижняя панель"
      }
    }
  }
}

css/light.css
--color-bg-surface: var(--gray-0);
Имя одно — color.bg.surface. Запись меняет сборщик по правилу: в CSS части соединяет дефис, в коде приложений их пишут слитно, каждую, кроме первой, с заглавной.

Переводит имена и единицы сборщик, например Style Dictionary. Он берёт файл токенов и собирает из него CSS, файлы для iOS и Android.

Имена в Figma

У переменной в Figma можно задать запись для кода: по одной для Web, iOS и Android. Это поле Code syntax в окне редактирования переменной.

Тогда в режиме разработчика (Dev Mode) в коде будет та запись, что в репозитории. Разработчику не придётся угадывать, как color/bg/surface называется у него.

Единицы

Отступ 16 в Figma — это пиксели. В CSS его часто пишут как 1rem, в iOS — 16 точек, в Android — 16 dp.

Это одно значение, если правило перевода записано. 1rem равен 16 пикселям, пока человек не поменял размер шрифта в браузере.

Если источник — репозиторий, размеры в файле держат в пикселях: встроенный импорт Figma принимает только px. В rem их переводит сборщик.

Одно имя, разная запись. Правило перевода имён и единиц записано один раз, и его выполняет сборщик, а не человек.

3Сверка макета и кода

Расхождения ищут по расписанию, а не когда их стало видно на экране. Видно обычно уже в продукте.

Ниже — восемь строк из сверки «Лесной обжарки»: слева переменная Figma, справа токен из CSS сайта.

Четыре строки — настоящие расхождения. Остальные только выглядят иначе. Нажимайте на строки, которые, по-вашему, надо чинить.

Сверка токенов · Figma и CSS сайта

  1. color/bg/page.Совпадает. Косая черта стала дефисом, а код цвета записан строчными. Это правило перевода, а не расхождение.
  2. color/bg/surface.Разные имена. Значение то же, но в коде токен называется по-своему. Новый разработчик не найдёт в коде color/bg/surface и заведёт ещё один токен. Переименовать в коде, старое имя оставить ссылкой на время перехода.
  3. color/text/secondary.Разные значения. 6B7580 вместо 5B6570. На глаз почти не видно, но контраст подписей на сайте не тот, что замеряли в макете. Взять значение из источника.
  4. color/action.Совпадает. С обеих сторон роль ссылается на примитив blue/600. Ссылку и сверяют, а не код цвета.
  5. space/inset/card.Совпадает. 1rem — это 16 пикселей при размере шрифта по умолчанию. Единицы разные по правилу перевода.
  6. radius/control.Разные значения. В коде 6, в макете 8. Кнопки и поля на сайте острее, чем в макете. Скорее всего, кто-то поправил на месте и не вернул в источник.
  7. color/bg/warning.Только в макете. Роль завели в Figma для плашки «Осталось 3 пачки», а в код она не попала. Разработчик подберёт жёлтый сам — и в тёмной теме его не будет.
  8. color/text/primary.Совпадает. Имя и значение одинаковые, регистр букв в коде цвета не важен.
Нажмите на любую строку сверки

Все четыре найдены. Другое имя, два других значения и токен, которого нет в коде. Регистр, разделители, единицы и ссылки вместо кодов — не расхождения, если правило перевода записано.

Нормальные строки тоже можно нажать: вы прочитаете, почему они совпадают, а счётчик «Найдено» не изменится.

Что считать расхождением

  • Токен есть только с одной стороны. В макете или только в коде.
  • Разные слова в имени. Разделители и регистр не в счёт.
  • Разные значения после приведения к одной записи: регистр кода цвета, единицы, ссылки на примитивы.
  • Разные значения в одном из режимов. Светлая тема совпадает, тёмная — нет.

Как сверять регулярно

Сверку делает скрипт, а не человек. Он берёт выгрузку из Figma и токены из кода, приводит записи к одной и печатает разницу.

Запускают его при каждом выпуске библиотеки и при каждой правке файла токенов в репозитории. Тогда расхождение живёт часы, а не месяцы.

Сверка — по расписанию и скриптом. Регистр, разделители и единицы приводят к одному виду, остальное разное — расхождение.

4Новый токен по порядку

Новый токен проходит один путь: документ, макет и код. Если его можно завести в обход, расхождения вернутся.

Каждый токен — обещание: имя не поменяется без предупреждения, значение есть во всех режимах.

Поэтому сначала решают, нужен ли он вообще.

Проверьте себя

В «Лесную обжарку» пришли восемь запросов. Какие токены стоит завести?

Тренажёр · заводить токен или нетвопрос 1 из 8 · 0 верно

  1. «Нужен color/bg/promo-autumn для баннера осенней акции».

    Не заводитьРазовый баннер без роли. Цвет остаётся значением в макете баннера, в наборе ему не место.

  2. «Ссылки в справке после перехода должны отличаться от новых — и в светлой, и в тёмной теме».

    ЗаводитьНовая роль с работой на экране и двумя значениями — color/text/link-visited.

  3. «Добавьте space/13: в макете кабинета так выглядит лучше».

    Не заводитьСтупени 13 в шкале нет. Это повод спросить, какая роль нужна, а не дописывать шкалу под один экран.

  4. «Рамку фокуса рисуем акцентом, но после смены бренда акцент станет светлым и рамка пропадёт».

    ЗаводитьУ фокуса своя работа и своя норма заметности. color/border/focus может ссылаться на тот же примитив, но меняется отдельно.

  5. «Для сайта кофейни-партнёра нужен color/bg/partner-green вместо нашего фона».

    Не заводитьЭто не новый токен, а новая тема: те же роли с другими значениями. В Figma — режим или, на Enterprise, расширенная коллекция для второго бренда.

  6. «Длительность анимаций — 150 мс — вписана в десяти местах кода».

    ЗаводитьПовторяется и меняется вместе. Токены бывают не только у цвета и отступов: у длительности в формате токенов есть свой тип.

  7. «Нужен color/blue-600-80: акцент с прозрачностью 80 % для одной тени».

    Не заводитьНи роли, ни второго места. Если таких теней станет много, понадобится роль тени, а не вариант синего.

  8. «У поля с ошибкой рамка красная, а роли для неё нет — берём цвет текста ошибки».

    Заводитьcolor/border/error. Совпадение цветов сегодня не значит, что завтра их поменяют вместе.

Токен заводят, когда у значения есть роль и оно меняется вместе в нескольких местах. Второй бренд — это тема, а не набор новых токенов.

Путь нового токена

Соберите путь токена color/text/link-visited по порядку. Один шаг лишний.

Конструктор · путь нового токена
  1. Запрос: где нужен токен и почему существующие не подходят Без запроса не понять, нужна ли новая роль или хватит старой. Посещённые ссылки — в справке, на двух экранах, color/text/link не подходит: он для новых ссылок.
  2. Имя по правилу и значения для всех режимов color/text/link-visited: категория, свойство, роль. Значения — примитивы для Light и Dark, у каждой пары с фоном замерен контраст.
  3. Строка в списке токенов и ревью Имя, роль, значения, где стоит. Ревью делают двое: от дизайна и от разработки.
  4. Изменение в источнике токенов Токен появляется там, где живут значения: в переменных Figma или в файле репозитория — смотря что у вас источник.
  5. Сборка: макет и код получают токен из источника Выгрузка или импорт, затем сборка для всех платформ. Руками значение не вписывает никто.
  6. Запись в списке изменений и сообщение командам Что добавилось, где применять, с какой версии. Добавление токена — новая возможность без поломок, то есть минорная версия.

Это лишний шаг: «Вписать цвет в макет справки, а токен завести потом». «Потом» обычно не наступает. Цвет остаётся вписанным, а в коде разработчик подбирает свой.

Цепочка пока пустая — начните с запроса.

Порядок записывают в документ системы. Тогда новый токен проходит путь без того, кто этот путь придумал.
Нет роли — нет токена. Новый токен проходит запрос, имя, ревью и попадает в макет и код из источника одним изменением.

5Как переименовать и убрать токен

Токен нельзя переименовать за один раз: на старое имя ссылаются макеты и код. Его выводят по шагам.

В сверке нашёлся --card-background. Правильное имя — color/bg/surface.

Если переименовать за один раз, сломается каждый экран, где стоит старое имя.

Четыре шага

  1. Завести новое имя и сделать старое ссылкой на него. Значение у обоих одно.
  2. Пометить старое как устаревшее. В формате Design Tokens Community Group для этого есть поле $deprecated: true или строка с пояснением, чем заменить.
  3. Перевести потребителей и объявить срок, после которого старого имени не будет.
  4. Убрать старое в следующей мажорной версии и записать это в список изменений.
Старое имя на время перехода
"card-background": {
  "$type": "color",
  "$value": "{color.bg.surface}",
  "$deprecated": "Заменён на color.bg.surface, будет убран в версии 3.0"
}
Старое имя показывает то же значение, что новое, и само говорит, чем его заменить.

Правило касается ролей, которыми пользуются экраны. Примитивы спрятаны внутри системы, их переименовывают без этих шагов.

Если источник — Tokens Studio, проверьте, переживёт ли пометка выгрузку. В «Лукоморье» пишут, что плагин не знает о старых именах и выгружает переименование как новый токен. Список замен там ведут отдельным файлом.

Это тот же порядок, что для компонентов. Как нумеровать версии и писать список изменений, разобрано в уроке «Компоненты и варианты», Senior.

Токен выводят, а не удаляют. Новое имя, старое — ссылкой с пометкой, перевод с объявленным сроком, удаление в мажорной версии.

6Задание

Сведите список токенов дизайна и кода, найдите расхождения и опишите порядок, по которому в продукт добавляется новый токен.

Часть 1 · Свести, 60 минут

  1. Выгрузите переменные из Figma в JSON и возьмите токены из кода: CSS, файлы приложений.

  3. Разложите разницу по видам: только с одной стороны, разные имена, разные значения, разные значения в одном из режимов.

Часть 2 · Починить, 60 минут

  1. Выберите источник и запишите его в документ.
  2. Каждое расхождение чините в источнике, а другая сторона получает значение сборкой.
  3. Разные имена сведите по четырём шагам вывода токена.

Часть 3 · Проверить путь, 30 минут

  1. Проведите один новый токен по порядку из документа.
  2. Запустите сверку снова. Новый токен должен совпасть с обеих сторон без ручных правок.
Как понять, что задание выполнено. Новый токен прошёл путь от документа до кода без вашего ручного вмешательства.

Что должно получиться

  • Документ токенов по шаблону: источник, правило имён, сверка, порядок добавления и вывода.
  • Сверка без расхождений или со списком тех, что выводятся по шагам.
  • Один токен, который прошёл весь путь.

План работы: 60 минут свести, 60 — починить, 30 — проверить путь. Всего около двух с половиной часов, плюс время разработчика на сборку.

Частые сложности

  • «В коде сотни значений без токенов». Не переводите всё сразу. Заведите токены, запретите новые значения в коде и переводите экраны по мере правок.
  • «Разработчики называют по-своему, и им так удобнее». Договоритесь о словах, а запись оставьте их языку. Правило перевода снимает большую часть спора.
  • «Выгрузку делаем руками и забываем». Это и есть главный риск ручного способа. Поставьте сверку в каждую сборку: забытая выгрузка всплывёт в тот же день.
  • «REST API недоступен на нашем тарифе». Встроенной выгрузки в JSON хватает. Её делают при каждом выпуске библиотеки, а сверку запускает сборка.

7Чек-лист и ошибки

Токены синхронны, если

  • У значений один источник, и он записан
  • Имена одинаковые по словам, запись переводит сборщик
  • Правило перевода имён и единиц записано
  • Сверка запускается скриптом при каждом выпуске и каждой правке токенов
  • Новый токен проходит путь из документа без обходов
  • Старые имена выводятся по шагам, с пометкой и сроком

Что мешает

  • Правка вне источника. Значение верное сегодня и разошлось завтра.
  • Свои слова в коде. --card-background вместо color/bg/surface.
  • Сверка глазами. Регистр и единицы отвлекают, настоящее расхождение пропускают.
  • Токен без роли. «Нужен на один баннер».
  • Переименование за один раз. Ломает каждый экран со старым именем.

8Три ступени темы

На первой ступени выносили значения в переменные, на второй — называли токены по ролям и собирали темы. Здесь токены становятся общими для макета и кода.

СтупеньЧто нужно уметьКак проверить результат
Junior Заводить переменные для цветов и отступов; привязывать к ним слои; называть по назначению; находить значения, вписанные руками Смена акцентного цвета всего макета — правка одного значения
Middle Разделять примитивы и роли; собирать имя токена по частям; собирать вторую тему режимом; находить прибитое Переключение темы не требует ни одной ручной правки в макете
Senior — этот урок Выбрать источник значений и способ передачи; держать одно имя на всех платформах; сверять макет и код скриптом; провести новый токен по порядку; выводить старые имена по шагам Новый токен проходит путь от документа до кода без ручного вмешательства
Ориентир по этой теме: вы можете сказать, где живёт значение любого токена, и знаете, через сколько часов правка в источнике окажется в продукте.
