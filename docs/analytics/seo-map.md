# SEO-карта DesignStack

> Этап 17, заведена 14.09.2026. Что и под какой запрос отвечает, как собираются title и description, что закрыто от индексации. Меняется вместе с сайтом: добавилась подборка — добавилась строка.

## Инструменты

SEO-плагина нет: разметка живёт в `designstack-core/includes/seo.php` и `schema.php` (решение D119).

Причина в том, что половина работы уже сделана своими руками. Canonical для архивов с фильтрами и закрытие пустых выборок написаны на этапе 14 — они завязаны на наши query vars, и любой плагин пришлось бы перехватывать. Разметку schema.org всё равно писать самим: типы записей у нас свои, плагин о них ничего не знает. Остаются title, description и Open Graph — это порядка двухсот строк, зато они собираются из полей записи автоматически, без ручного заполнения ста сорока карточек.

Чем платим: нет окошка в админке, чтобы поправить описание одной страницы руками. Понадобится — заводим поле `seo_description` в плагине, это полдня.

Штатный `wp-sitemap.xml` остаётся: он умеет всё, что нужно каталогу.

## Шаблоны title и description

Собираются из полей записи, руками ничего не пишется.

| Тип страницы | title | description |
|---|---|---|
| Главная | `Проверенные ресурсы для UX/UI-дизайнера — DesignStack` | Из лида главной, до 160 знаков |
| Архив типа | `{Тип}: {N} проверенных ресурсов для дизайнера — DesignStack` | `{Подпись раздела}. У каждого — цена, доступ из России и дата проверки.` |
| Архив с одним фильтром | `{Тип}: {значение фильтра} — DesignStack` | `{N} ресурсов: {значение фильтра}. Цена, доступ из России и дата проверки у каждого.` |
| Тема | `{Тема} для дизайнера: {N} ресурсов — DesignStack` | То же, с названием темы |
| Карточка | `{Название} — {вердикт} — DesignStack` | `{review_for} {review_why}` обрезано до 160 знаков по границе слова |
| Подборка, дайджест, обзор | заголовок записи как есть + ` — DesignStack` | `post_excerpt` |
| О проекте, Предложить | заголовок страницы + ` — DesignStack` | первый абзац до 160 знаков |
| Поиск, витрина, 404 | заголовок + ` — DesignStack` | нет (страницы закрыты от индексации) |

Правило длины: title до 60 знаков считая бренд — иначе поисковик обрежет; description 120–160. Вердикт у нас и так ≤ 120, поэтому в title карточки он помещается.

## Что закрыто от индексации

Решение D120: в поиск пускаем архив без фильтров и архив с **одним** фильтром; два и больше — закрываем.

| Страница | Индексация | Canonical |
|---|---|---|
| Архив без фильтров | индексируется | на себя |
| Архив, один фильтр (`/tools/?pricing=free`) | индексируется | на себя |
| Архив, два фильтра и больше | `noindex, follow` | на архив без фильтров |
| Архив с нулевым результатом | `noindex, follow` | на архив без фильтров |
| Сортировка, отличная от «сначала проверенные» | индексируется | на архив без параметров |
| Страница пагинации от второй | индексируется | на себя |
| Поиск и `/?s=` | `noindex, follow` | — |
| `/styleguide/` | `noindex, nofollow` | — |
| Страница благодарности за форму | `noindex, follow` | — |

Записи со статусом «Закрыт» из индекса не убираем: страница остаётся ради истории и ссылки на аналог (brief §5), а по запросу «{название} что случилось» она полезнее пустоты.

## Sitemap и robots.txt

Штатный `/wp-sitemap.xml`. Исключены: витрина, страница благодарности, вложения, страницы с `noindex`. Фильтры в sitemap не попадают по определению — WordPress кладёт туда только чистые адреса.

`robots.txt` собирается фильтром `robots_txt` в плагине:

```
User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php
Disallow: /search/
Disallow: /*?s=
Disallow: /styleguide/
Disallow: /thanks/
Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&ut_task
Sitemap: https://designstack.ru/wp-sitemap.xml
```

`Clean-param` — для Яндекса: без него метки из Telegram и юзер-тестов размножат адреса в индексе.

## Чеклист после деплоя (этап 19)

Браузерные шаги делает заказчик, результат — в `PROJECT.md` без токенов.

1. Яндекс Вебмастер: добавить сайт, подтвердить мета-тегом (значение кладём в опцию `designstack_verification_yandex`), отправить sitemap, проверить регион, включить «Быстрые ссылки».
2. Google Search Console: добавить ресурс, подтвердить мета-тегом (`designstack_verification_google`), отправить sitemap.
3. Проверить разметку: validator.schema.org, Rich Results Test, Вебмастер → «Проверка микроразметки».
4. Проверить `blog_public = 1` на продакшене: локально значение ни на что не влияет, а на живом сайте ноль закрывает сайт целиком.
5. Прогнать OG-превью: отправить ссылку самому себе в Telegram и посмотреть карточку.
