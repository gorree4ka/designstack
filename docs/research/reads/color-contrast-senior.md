## 1. Design tokens и Color roles

- Адрес: https://m3.material.io/foundations/design-tokens/overview, https://m3.material.io/styles/color/roles
- Прочитано: целиком обе страницы. - https://m3.material.io/foundations/design-tokens/overview — обе вкладки, Overview и How to use tokens, через JSON `.../abae98fd-d828-44f8-bb66-9ee8746f6073.json` (обновлено 17.07.2026). - https://m3.material.io/styles/color/roles — через JSON `.../ced25aa3-a367-44c6-a47e-439bc9e59d68.json`. - Дополнительно — M3 Color system (Overview и How the system works) и `color_spec_2021.ts` Material Color Utilities.
- Что это: Google, Material Design 3, справка. На английском, около 12 + 12 минут. Уровень Senior.
- Что в нём на самом деле: - Design tokens: - «three classes of tokens: reference, system, and component» (ref, sys, comp). - Reference — все значения, от контекста не зависят. System — «This is where theming occurs», могут указывать на разные reference в светлой и тёмной теме. Component — «in development», должны указывать на system или reference. - Контексты: тёмная тема, плотность, форм-фактор, RTL. Разбор имени md.ref.palette.secondary90. Outline variant — для декоративных разделителей, и «Don't use the outline color for dividers». - Дополнительные роли: fixed, fixed dim, surface bright/dim.

## 2. Color, Accents и Design tokens

- Адрес: https://atlassian.design/foundations/color, https://atlassian.design/foundations/color/accents, https://atlassian.design/foundations/tokens/design-tokens
- Прочитано: целиком — https://atlassian.design/foundations/color и https://atlassian.design/foundations/color/accents. Дополнительно, потому что урок опирается: - https://atlassian.design/foundations/tokens/design-tokens; - https://atlassian.design/foundations/color/color-palette (имена Red100…Red1000); - https://atlassian.design/foundations/tokens/use-tokens-in-code; - правило ESLint https://atlassian.design/components/eslint-plugin-design-system/ensure-design-token-usage/usage.
- Что это: Atlassian Design System, справка, © 2026. На английском, около 8 + 5 минут. Уровень Senior.
- Что в нём на самом деле: - Color: - Насыщенные, нейтральные (отдельно для светлой и тёмной темы) и альфа-цвета. - Цвет применяется только токенами. Имя: «color» + свойство (background, border, icon, text) + модификаторы роли, уровня выделения и состояния — «color.background.danger.bold.hovered». - Роли: neutral, brand, information, success, warning, danger, discovery, accent, inverse, input. «Don't use an accent when the color has semantic meaning». - Уровни выделения от subtlest до boldest. Inverse-токены на ярких фонах, отдельные warning.inverse. - Состояния hovered, pressed, selected, focused, disabled. - Нормы 3 : 1 и 4,5 : 1 с границей 24 px. Две темы, светлая и тёмная. - Accents: - «10 accent colors», для стикеров, выбора цвета, иконок проектов и категорий. - Проверка «можно ли заменить на другой без изменения смысла». Не брать для information, warning, success. - Уровни фона и текста, допустимые пары для контраста. Жёлтый не брать: он «becomes brown». Рамка вокруг бледного фона ради 3 : 1, не смешивать акценты разных цветов.
- Строка «зачем» против текста: [color-contrast-senior] — верно.
- Спорит с уроком: нет. - Урок опирается на источник: - Таблица раздела 3, имена токенов «color.background.danger, color.text.subtle, color.border.focused, color.icon.warning» — существующие токены. - «Палитра, например Red100 и Red1000» — есть, но на странице Color palette, на которую Color ссылается. - «Прибитые значения их линтер считает нарушением» — на страницах из списка нет. Есть на странице правила ESLint: «Using anything other than design tokens such as hardcoded values or legacy theme colors will be considered violations». - «не берите токен только потому, что цвет совпал, — в другой теме это сломается» (и в разделе 4 «Atlassian об этом прямо предупреждает») — на страницах из списка нет. Есть на странице Design tokens: «Don't use a token just because the colors appear to match. This can break the experience in other themes». - «десять цветов без смысла, для меток и категорий, которые выбирает сам человек. Их нельзя брать там, где у цвета есть значение, например для предупреждения» — верно, Accents.
- Урок приписывает источнику: —
- Решение: переписать строку и добавить третью ссылку — https://atlassian.design/foundations/tokens/design-tokens, на ней стоит правило, которое урок цитирует.

## 3. Color usage

- Адрес: https://primer.style/product/getting-started/foundations/color-usage/
- Прочитано: целиком — https://primer.style/product/getting-started/foundations/color-usage/ (все разделы; блок Base colors — встроенный Storybook, прочитана подпись).

- Что в нём на самом деле: - Два цветовых режима на девяти темах. - Токены трёх групп: Base («color-scale-pink-5»), Functional («borderColor-sponsors-emphasis»), Component/pattern («focus-outlineColor», их мало, предпочтительны функциональные). «Base color tokens don't respect color modes and should never be used directly in code or design». - Нейтральные шкалы 0–13, светлая и тёмная, направлены навстречу друг другу, поэтому темы делят функциональные токены. - Ступени: фоны — первые шесть; рамки — 7–8, ступень 8 — минимум для рамки элемента; текст — 9–10. ## 5. Design Tokens Format Module 2025.10 и Resolver Module

- Адрес: https://www.designtokens.org/tr/2025.10/format/, https://www.designtokens.org/tr/2025.10/resolver/
- Прочитано: целиком — https://www.designtokens.org/tr/2025.10/format/, разделы 1–9 и приложения, все 58 примеров. Дополнительно — обзор модулей https://www.designtokens.org/tr/2025.10/ и аннотация https://www.designtokens.org/tr/2025.10/resolver/.
- Что это: - Design Tokens Format Module 2025.10, W3C Design Tokens Community Group. Final Community Group Report от 28.10.2025, «considered stable», при этом «not a W3C Standard nor is it on the W3C Standards Track». - Редакторы: Louis Chenais, Kathleen McMahon, Drew Powers, Matthew Ström-Awn, Donna Vitan. - На английском, техническая спецификация для авторов инструментов, около 60 минут. Уровень Senior (и разработка).
- Что в нём на самом деле: - Цель: общий JSON-формат для обмена токенами между инструментами дизайна, перевода в код и документации. Тип файла application/design-tokens+json, расширения .tokens / .tokens.json. - Токен — объект с $value; $type, $description, $extensions (данные инструментов, их надо сохранять), $deprecated. - Группы, наследование $type, $root, $extends (как $ref в JSON Schema). - Ссылки: {group.token} на целый токен и JSON Pointer $ref на часть значения, цепочки ссылок, запрет циклов. - Типы: - color — только отсылка к отдельному Color Module, в примерах colorSpace / components / hex; - dimension (px или rem); - fontFamily, fontWeight; - duration — объект {value, unit}, unit только «ms» или «s»; - cubicBezier — массив [P1x, P1y, P2x, P2y], x в диапазоне [0, 1]; - number. - Составные типы: strokeStyle, border, transition (duration, delay, timingFunction), shadow, gradient, typography. - Figma упомянута дважды: в списке инструментов дизайна и в примере, что она не поддерживает линии inset, outset и double. - Светлой и тёмной темы в этом модуле нет. Их описывает отдельный Resolver Module 2025.10 («multiple contexts (such as “light mode” and “dark mode” color themes)»).
- Строка «зачем» против текста: - [color-contrast-senior] — неточно. - «Тип color» — в модуле только отсылка к отдельному Color Module и примеры. - «Ссылки на другие токены» — верно, раздел 7. - «Обмен между Figma и кодом» — спецификация про обмен между любыми инструментами. Figma в ней только в списке примеров, о поддержке формата в Figma там ничего нет. - Для урока про две темы главное: темы в этот модуль не входят. - [motion-senior] — верно: типы duration и cubicBezier описаны, запись совпадает с примером урока. Строка не говорит про составной тип transition и про то, что пружин в формате нет.
- Спорит с уроком: нет. Пример JSON в motion-senior валиден: `{ "value": 200, "unit": "ms" }`, `[0, 0, 0, 1]`, `[0.3, 0, 1, 1]` — x в пределах [0, 1]. - Урок опирается на источник: - [color-contrast-senior], раздел 8: «Сообщество W3C по дизайн-токенам в октябре 2025 года выпустило первую стабильную версию формата — 2025.10» — верно. - Там же: «и Figma умеет импортировать токены в нём» — в спецификации этого нет. Справка Figma по поисковой выдаче help.figma.com говорит, что импорт переменных принимает JSON в формате DTCG; страницу справки целиком не читал. - [motion-senior], раздел 2: «Для обмена между макетом и кодом есть формат дизайн-токенов W3C» — формулировка создаёт впечатление стандарта W3C, а документ прямо говорит «not a W3C Standard». Точнее: «формат сообщества W3C по дизайн-токенам».
- Урок приписывает источнику: —
- Решение: переписать обе строки. Для senior предложить вторую ссылку на Resolver Module (https://www.designtokens.org/tr/2025.10/resolver/) — там светлая и тёмная темы.
- Строка на сайте: Стабильный с октября 2025 года JSON-формат для обмена токенами между инструментами: как записать токен, группу и ссылку на другой токен вида {color.brand}.
