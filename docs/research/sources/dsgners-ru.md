# Конкурентный разбор: dsgners.ru (основной) + dssign.ru (сравнение)

Дата разбора: 10.09.2026. Аналитик: Senior Product Designer / конкурентная аналитика.
Заказчик: DesignSite — русскоязычный каталог ресурсов для UX/UI-дизайнеров.
Наши дифференциаторы, которые проверяем у конкурентов: (а) актуальность (дата проверки + статус
«работает / изменилось / закрыт»), (б) доступность из РФ (метка + локальный аналог),
(в) редакторская оценка куратора вместо описания вендора.

Метод: curl (server-side HTML; страна IP не замерялась, O8 в `docs/DECISIONS.md`), sitemap.xml/robots.txt, грепы разметки,
массовая проверка внешних ссылок через `curl -sIL -w "%{http_code} %{url_effective}"`.

## 1. Модель контента

**Главный вывод: dsgners.ru — не каталог ресурсов, а UGC-медиа.** Self-description в og:title:
«дизайнерс — контентная платформа для цифровых и графических дизайнеров»; description:
«На платформе свободные дизайнеры и бизнес пишут статьи, дайджесты и уроки, делятся
профессиональными кейсами и обсуждают актуальные новости индустрии» (https://dsgners.ru/, og-теги).
Стек: Laravel + Inertia.js + Vue (SSR-HTML содержит `data-page` с полным JSON пропсов —
все цифры ниже взяты из него, а не с глаз).

### Типы записей (`site_data.post_types`, ровно 5)
| id | url | Тип |
|----|-----|-----|
| 1 | /news | Новость |
| 2 | /articles | Статья |
| 4 | /class | Урок |
| 10 | /cases | Кейс |
| 11 | /digest | Дайджест |

Отдельного типа «ресурс / инструмент / сервис» **нет**. Ссылки на инструменты живут внутри
тела постов типа «Дайджест» и «Статья» — то есть как проза, а не как данные.

### Объём (sitemap.xml, 10.09.2026)
- `sitemap-posts-0.xml` + `sitemap-posts-1.xml` = **9 380 постов**
- `sitemap-users-0.xml` = **1 453 профиля авторов**
- `sitemap-tags.xml` = **12 тегов**, `sitemap-pages.xml` = **4 статические страницы** (/, /about, /rules, /ads)
- Постов с URL-паттерном подборки (`daydjest|podborka|instrument|plagin|servis`) — **666**
- Распределение по `lastmod`: 2023 — 1 447, 2024 — 1 869, 2025 — 2 965, 2026 (9 мес.) — 2 903.
  Платформа растёт, ~10–12 публикаций в день.
- Баг данных: у 13 записей `lastmod` вида `-0001-11-30` (нулевая дата) — попали в sitemap как есть.

### Поля карточки в списке (`lenta.posts[]`, полный список ключей)
`id, url, image, title, descr, type_id, published_at, tags[], author{id,avatar,name,login,url,
is_deleted,is_verified,is_editorial,is_business}, reactions{5 типов}, comment_count,
favorite_count, user_favorite, views_coverage_count, views_prev_count, views_count,
is_popular, is_legacy, is_business`

Что важно: **в карточке списка есть только `published_at`** — даты обновления/перепроверки нет
ни в данных, ни в UI. Реакций пять: `{1:heart, 2:smile, 3:stone, 4:fire, 5:wow}` («камень» —
дизлайн-эквивалент).

### Поля карточки в детали (`props.post` на странице поста)
`id, image, title, body_is_legacy, body, type_id, updated_at, published_at, tags[],
primary_tag_id, author, is_editorial, reactions, comment_count, favorite_count, user_favorite,
views_coverage_count, views_prev_count, views_count, share_urls, body_image_path, allow_edit, is_legacy`
Плюс отдельные пропсы страницы: `post_menu`, `curator`, `other_author_posts`.

**`updated_at` есть в данных, но он технический и врёт.** Пост
https://dsgners.ru/designarchivist/988-veb-dizayn-95-luchshih-resursov-dlya-poiska-vdohnoveniya-v-2023-godu
имеет `published_at: 2023-06-30 14:27:55`, а `updated_at: 2026-09-10 14:35:05` — то есть
«сегодня, минуту назад», потому что поле трогает счётчик просмотров/кэш, а не редактор.
В интерфейсе `updated_at` не показывается вообще. Для читателя единственная дата — дата
публикации трёхлетней давности.

### Категории и теги
Тегов ровно **12**, плоский список без иерархии, у каждого свой ico:
Продуктовый дизайн, Типографика, Motion, Графический дизайн, UX, AI, UI, Карьера, Креатив,
Брендинг, 3D, Мнение (`props.filter.elems.tags`). Категорий как отдельной сущности нет —
её роль играет `type_id`. Оси «платно/бесплатно», «доступно из РФ», «этап процесса»,
«для чего инструмент» — отсутствуют полностью.

### Кто наполняет
UGC + бизнес-аккаунты + редакция, всё в одной ленте, различаются только флажками автора:
`is_verified`, `is_editorial`, `is_business`, `is_deleted`. В выдаче «Популярное» 10.09.2026
из 11 постов: 1 верифицированный бренд (Авито), 1 бизнес-аккаунт (Евгения Шамрай),
1 верифицированный автор (#ФФДД2Д), остальные — обычные пользователи, включая явно
промо-посты (никита xmentors.ru, KISLOROD, Paratype). Модерация постфактум и мягкая:
промо-контент курсов и агентств идёт в общей ленте на равных с редакционным.
Есть геймификация: рейтинг авторов по сезонам (`rating2_on: true`), бейджи
(«Триумфатор рейтинга s1’25», тип «Легендарное»), счёт в баллах (лидер — 6 080).

статьи. И пометка партнёрских ссылок должна работать не только для баннеров, но и для карточек.

## 2. Навигация и поиск

### Разделы
Верхнее меню (`site_data.menu_main`): **Лента / Рейтинг / Подписки / Избранное** — то есть
навигация организована вокруг *ленты и социального графа*, а не вокруг предметной области.
Разделы по типу контента (`/news`, `/articles`, `/class`, `/cases`, `/digest`) в главном меню
**отсутствуют** — до них доходишь только через фильтр или прямой URL.
Служебное меню (`menu_main_adv`): О проекте (`/about`), Реклама (`/ads`), Правила (`/rules`),
Поддержка (`/feedback`). Копирайт в футере: «© 2023-2026» — проект стартовал в 2023.

### Фильтры
Есть, три оси, все в одном компоненте `Main` (`props.filter`):
- **mode**: Популярное / Свежее / Моя лента / Фильтр (последний открывает расширенный набор);
- **time**: За все время / За неделю / За месяц / За год;
- **tags**: 12 тегов; **types**: 5 типов записи.
Ось «доступно из РФ», «платно/бесплатно», «этап работы» — нет ни одной.

**В URL фильтры не попадают.** Проверка: `https://dsgners.ru/digest` отдаёт
`filter.current_vals = {"mode":"filter","time":0,"tags":[],"types":["11"]}` — то есть раздел
это *пресет фильтра*, а не отдельный шаблон; но пользовательская комбинация (тег + период + тип)
живёт в состоянии Vue и не отражается в адресе. Косвенное подтверждение — `robots.txt`:
`Disallow: /filter?`. Итог: **отфильтрованную выдачу нельзя ни расшарить, ни забукмаркать,
ни вернуться в неё кнопкой «назад»**. Ссылочный вес фильтров тоже никуда не идёт.
Теги при этом собственные URL имеют (`/ui`, `/ux`, `/product-design`, … — 12 шт. в sitemap-tags.xml).

### Поиск
`GET /search?q=…` (роут `site.search.page`; есть и легаси `/search-old`). Ищет по двум сущностям —
`posts[]` и `users[]`, `start_limit: 5`. Есть история запросов
(`api/v1/search/searchHistory` — сохранение, чтение, удаление).
- **Фильтров и сортировки в поиске нет вообще** — ни по типу, ни по тегу, ни по дате.
- Поиск закрыт от индексации (`Disallow: /search`).
- **Пустая выдача — тупик.** Проверка `https://dsgners.ru/search?q=zzqqxvv123` → `posts: []`,
  `users: []` и единственная строка: «По вашему запросу ничего не найдено, попробуйте
  изменить запрос». Ни исправления опечатки, ни популярных запросов, ни ссылки на разделы,
  ни «сообщить, чего не хватает».

### Сортировка и пагинация
Сортировка = ось mode (Популярное / Свежее), отдельного «по дате обновления» нет — да и нечего
сортировать, поля нет. Пагинация — подгрузка по `next_page_exist: true` через API;
**crawlable-страниц `?page=2` нет**, `<link rel="next">` отсутствует, canonical на `/digest`
без параметров. Весь глубокий архив (9 380 постов) доступен поисковику только через sitemap,
не через навигацию.

### Карточка: страница или модалка
Страница. URL вида `/{author_login}/{id}-{slug}` (`post.view`), SSR-разметка полноценная:
на главной 38 уникальных `<a href>` на посты, у каждого — картинка, заголовок, описание,
счётчики. Модалки (`?modal=`, 13 упоминаний `popup` в разметке) используются для авторизации,
шаринга и поиска, но не для контента. Формально это правильно; проблема в другом —
**в карточке нет ни одного поля, которое отвечало бы на вопрос «это ещё актуально?»**.
На детали поста единственная дата — «Статья · 30.06.23».

**Что нам с этого:** три вывода. (1) Наш фильтр обязан жить в URL — каталог без
шарящихся состояний фильтра теряет и SEO, и рабочие сценарии («скинь коллеге подборку
бесплатных RU-доступных прототипов»). (2) Пустая выдача — это наш шанс: там место кнопке
«предложить ресурс» и подсказке «похожие по тегу». (3) Оси фильтра — наш главный
дифференциатор: `статус`, `доступ из РФ`, `цена`, `этап процесса` вместо их «популярное/свежее».

## 3. Монетизация

Источник — публичная страница https://dsgners.ru/ads (прайс открытый, что редкость).

### Баннерная реклама (основной поток)
| Формат | 30 000 показов | 60 000 показов | 120 000 показов |
|---|---|---|---|
| Растяжка в шапке | 24 000 ₽ (CPM 800) | 42 000 ₽ (CPM 700) | 72 000 ₽ (CPM 600) |
| Баннер в лентах «Популярное»/«Свежее» | 18 000 ₽ (CPM 600) | 30 000 ₽ (CPM 500) | 48 000 ₽ (CPM 400) |
| Баннер под комментариями | 15 000 ₽ (CPM 500) | 24 000 ₽ (CPM 400) | 36 000 ₽ (CPM 300) |

Показ засчитывается «при отображении на экране от 80 % площади» — прозрачная методика.
Реклама промаркирована по 38-ФЗ: в `site_data.banners` лежат `advertiser`, `advertiser_token`
(erid), `label_show: true`. На 10.09.2026 обе позиции (растяжка + боковой) заняты одним
рекламодателем — ai-nation.ru, «ИП Крутов Дмитрий Валерьевич, ИНН 772973192199»
(Дмитрий Крутов — основатель Skillbox); внутреннее имя кампании «1 | Крутов | 20.08.2026».
То есть весь инвентарь на день проверки выкуплен одним игроком EdTech.

### Платные статьи — и это главная проблема с доверием
Цитата с /ads: «Наша команда редакторов составит бриф, и напишет по согласованному с вами
структуре материал любого формата. **Вам останется только опубликовать его в своём профиле.**»
Механика: заказная статья публикуется не как реклама, а как обычный пост бренда в общей ленте.
В `post`-объекте нет ни одного поля вида `is_adv` / `is_sponsored` — только `is_business`
и `is_editorial`, которые обозначают *тип аккаунта*, а не оплаченность конкретного материала.
Кейсы, названные самим проектом: Яндекс.Практикум, hh.ru, Bauns.
Вывод: **баннер помечен, нативка — нет.**

### Продвижение через медиасеть
«Нативно прорекламируем вашу статью через нашу медиасеть Telegram-каналов и групп во ВКонтакте» —
то есть проект продаёт не только свой инвентарь, но и посев во внешней сети каналов.
Отдельный юнит «дизайнерс медиа», «занимаемся рекламой и продвижением уже 6 лет».
Плюс спецформаты (стримхата «Mish Let’s Play»: 1 917 подписчиков в TG клиента,
32 744 уникальных зрителя эфиров).

### Курсы: модуль построен и выключен
В роутах (`ziggy.routes`, 146 шт.) целиком присутствует образовательное направление:
`/education`, `/studio/education`, `/studio/education/curator`, `/studio/education/stats`,
`/studio/education/stats/csv`, `api/v1/education/course/{id}/publish`, `api/v1/education/school`,
`api/v1/board/edu/view`, `api/v1/board/edu/click`, вкладка профиля `/{user_login}/education`.
При этом в пропсах `edu_visible: false` и `edu_feed_block: false` — **маркетплейс курсов
со школами и кураторами написан, но на 10.09.2026 скрыт**. Это либо свёрнутая попытка
второй монетизации, либо релиз на паузе.

### Партнёрские ссылки
Классических affiliate-ссылок в контенте не обнаружено: в проверенных 95 ссылках поста 988
нет ни одного `ref=`/`aff=`/`partner=` (единственный `?ref=` дописал сам сервис при редиректе).
Партнёрка как модель не используется — деньги берут напрямую с рекламодателя.

**Что нам с этого:** прайс dsgners.ru — готовый бенчмарк для нашей рекламной модели
(CPM 300–800 ₽ на аудитории дизайнеров в РФ). Но их главную ошибку копировать нельзя:
как только заказная статья идёт в ленту без метки, обещание «редакторская оценка куратора»
превращается в тыкву. У нас должно быть жёстко: поле `is_paid` / `partner_link` на карточке
ресурса, видимая метка, и отдельная лента «партнёрские» — иначе весь дифференциатор
«оценка куратора вместо описания вендора» не стоит ничего.

### Трафик (самозаявленное, страница /ads, актуальна на 10.09.2026)
- «**>120 000 уникальных пользователей ежемесячно**» — и тут же ниже, в блоке про баннеры,
  «стабильно **от 100 000** уникальных посетителей ежемесячно». Цифры в одном документе
  расходятся на 20 % — оценка, а не измерение.
- «Более **20 000 зарегистрированных** пользователей» (в sitemap-users 1 453 профиля —
  то есть в индекс попадают только заполненные/активные, ~7 %).
- Структура трафика: «более **75 % органически** — из поисковых систем (**41,8 %**)
  и через прямые заходы (**35 %**)».
- Аудитория: 18–34, UX/UI-, продуктовые, графические и веб-дизайнеры, преимущественно
  Москва и Санкт-Петербург; «более 90 % тех, кто увидит рекламу — дизайнеры».

### Сверка с наблюдаемым (оценка)
Медианный охват поста в выдаче «Популярное» 10.09.2026 — 630–1 200
(`views_coverage_count`), у дайджестов 1 200–2 800, у топового поста-каталога за 3 года — 15 758.
При ~10–12 публикациях в день это даёт порядок 300–500 тыс. просмотров постов в месяц,
что с заявленными 100–120 тыс. уникальных согласуется. **Оценка: реальный масштаб —
первые сотни тысяч визитов в месяц, львиная доля из поиска на «длинный хвост» из 9 380 постов.**

### SEO
- Технически сделано аккуратно: SSR-разметка (на главной 38 уникальных `<a href>` на посты),
  `rel=canonical` на каждой странице, sitemap-индекс из 5 файлов, продуманный `robots.txt`
  с `Clean-param: comments&y_ref` и авторскими комментариями внутри файла.
- Видимость строится на **длинном хвосте пользовательских статей**, а не на кластере
  каталожных запросов. Своих посадочных под «сервисы для дизайнеров», «инструменты для
  UX-исследований», «аналоги Figma в России» у проекта нет — только 12 тегов и 4 статические
  страницы. Поисковый вход — конкретные заголовки статей («как я собрала скилл для
  дизайна B2B-интерфейса», «дизайнить карточки на маркетплейсы»).
- Слабое место: листинги глубже первой страницы не краулятся (нет `?page=2`, нет `rel=next`),
  фильтры не в URL, `/search` закрыт. Весь глубокий архив держится только на sitemap.
- Утечка в проде: в `ziggy.routes` наружу отдаются роуты Laravel Debugbar (`_debugbar/*`)
  и Ignition (`ignition.executeSolution`, `ignition.updateConfig`) — на боевом сайте
  их быть не должно.
- Ещё любопытное: в роутах есть `content.generate-topics`, `content.check-duplicates`,
  `content.generate-articles` — внутренний AI-генератор тем и статей с проверкой дублей.

**Что нам с этого:** 19 тыс. в Telegram и ~100–120 тыс. уников в месяц — это верхняя планка
ниши в рунете, и взята она чистым UGC-объёмом, а не структурой. Ниша каталожных запросов
(«чем заменить X в России», «бесплатные инструменты для Y») ими **не занята вообще** —
там нет ни посадочных, ни фильтров в URL. Для нас это прямой SEO-вход. И канал возврата
надо строить сразу двойной: Telegram + email-дайджест «что изменилось в каталоге за месяц» —
у них второго нет.

### Почему проект не стал стандартом — версия

1. **Он решил задачу медиасети, а не задачу дизайнера.** Медиасеть на 2 млн подписчиков
   искала, куда сливать трафик, — так появился сайт. Отсюда навигация вокруг ленты
   (Лента/Рейтинг/Подписки/Избранное), а не вокруг задачи «найти инструмент».
   Пользователь приходит из TG на конкретный пост и уходит; возвращаться не за чем,
   потому что структуры, к которой можно вернуться, нет.
2. **Стандартом становится справочник, а не поток.** Стандарт — то, что открывают,
   когда нужно найти. У dsgners нет ни одной сущности, которую можно «найти»:
   ни ресурса, ни инструмента, ни компании — только 9 380 постов и 12 тегов.
3. **Актуальность не является продуктом.** Пост-каталог трёхлетней давности с 15,8 %
   битых и подменённых ссылок висит в топе выдачи с датой «30.06.23» и без единой пометки.
   Никто не отвечает за то, что ссылка ещё работает, — значит, доверять каталогу нельзя,
   значит, он не становится точкой входа.
4. **Модерация «лайтовая» по признанию основателя.** Когда фильтр — «отказываем только
   совсем рекламным», а редакция сама пишет заказные статьи для публикации «в вашем профиле»,
   граница между оценкой и рекламой стирается. Стандарт требует независимой позиции.
5. **Не занята повестка «после 2022».** Ни метки доступности из РФ, ни локальных аналогов,
   ни цен в рублях, ни оплаты — при том, что это ежедневная боль аудитории. Проект
   продолжает публиковать подборки западных сервисов как ни в чём не бывало.
6. **Один канал возврата.** Только Telegram; нет рассылки, нет «что изменилось»,
   нет уведомлений об обновлении карточки. Retention держится на ленте, а лента
   конкурирует с самим TG-каналом на 19 тыс. человек — и проигрывает ему по удобству.

**Что нам с этого:** ниша свободна не потому, что туда не заходили, а потому, что заходили
с медийной стороны. Медиа отвечает за поток и охват; каталог отвечает за то, что запись
верна на дату проверки. Это разные обязательства и разные операционные процессы (у нас —
регулярный ре-чек и статусы, у них — публикация и продвижение). Прямой конкуренции почти
нет: dsgners можно рассматривать как канал дистрибуции (их же «медиасеть» продаётся)
и как источник сигналов о том, какие ресурсы вообще упоминают.

## 6. Когнитивный обход флоу «главная → раздел → карточка → переход по ссылке»

Задача пользователя, взятая как эталон: **«найти рабочий инструмент для UX-исследований,
который открывается из России и не требует зарубежной карты».**
На каждом шаге — четыре вопроса когнитивного обхода (Wharton/Polson):
(1) поймёт ли пользователь, какую цель тут преследовать; (2) заметит ли он нужное действие;
(3) свяжет ли действие с целью; (4) поймёт ли по отклику системы, что продвинулся.

### Шаг 1. Главная https://dsgners.ru/
1. **Поймёт ли цель?** Нет. Заголовок «контентная платформа для цифровых и графических
   дизайнеров», под ним лента разнородных постов («ДИгадка №42», «Расписание ИТ-мероприятий
   Москвы»). Ничто не сообщает, что здесь можно что-то *найти*, — только читать.
2. **Заметит ли действие?** Частично. Видны «Популярное / Свежее / Моя лента / Фильтр»
   и меню Лента/Рейтинг/Подписки/Избранное. Все четыре пункта меню — про социальный граф,
   ни один не про предметный поиск. Поле поиска есть, но не выделено как основной путь.
3. **Свяжет ли с целью?** Нет. Нет ни слова «инструменты», «сервисы», «ресурсы» ни в меню,
   ни в разделах. Ближайшее, «Фильтр» → тип «Дайджест», требует знания, что подборки
   называются дайджестами.
4. **Поймёт ли отклик?** Отклик есть (лента перестраивается), но он не приближает:
   отфильтрованная выдача — те же статьи, только другие.

### Шаг 2. Раздел https://dsgners.ru/digest
1. **Цель шага понятна?** Отчасти: заголовок «дайджест на дизайнерс… сборник всех дайджестов».
   Но «дайджест» смешивает три разные вещи: новостной обзор недели, промо-подборку курса
   и каталог из 95 ресурсов — они выглядят одинаково.
2. **Действие заметно?** Да, карточки кликабельны, картинка — реальный `<a href>`.
3. **Связь с целью?** Слабая. Отличить «Дайджест новостей за неделю (22.08.26 — 28.08.26)»
   от «95+ лучших ресурсов» можно только по названию; фильтра «подборки инструментов» нет.
4. **Отклик?** Здесь ломается: пользователь докручивает ленту (подгрузка без URL страниц),
   уходит в статью — и, вернувшись, **получает ленту с начала и сброшенными фильтрами**
   (подтверждено и технически, и цитатой UX-разбора Habr).

### Шаг 3. Карточка (пост) — пример поста 988
1. **Цель понятна?** Да: заголовок «Веб-дизайн: 95+ лучших ресурсов…».
2. **Действие заметно?** Да, но нерелевантное: реакции, «в избранное», «подписаться»,
   комментарии. Действия «проверить, живо ли», «отфильтровать по доступности» нет.
3. **Связь с целью?** Нарушена. Единственная дата на странице — «Статья · 30.06.23»,
   ей три года. Никакого сигнала «проверено», «обновлено», «часть ссылок мертва».
   Внутренний `updated_at` показывает «10.09.2026 14:35», но пользователю не показывается
   и всё равно врёт (его трогает счётчик, а не редактор).
4. **Отклик?** Наихудший вариант — **ложноположительный**: страница выглядит живой
   (свежие комментарии, счётчик 15 758), и пользователь верит списку, в котором
   каждая шестая ссылка не туда.

### Шаг 4. Переход по внешней ссылке
1. **Цель?** Да, тривиально.
2. **Действие?** Да, ссылка синяя и кликабельная.
3. **Связь?** Нет предупреждения: ни `target`-подсказки, ни метки «внешняя», ни статуса,
   ни цены, ни «нужен VPN/зарубежная карта».
4. **Отклик?** У 9,5 % ссылок — 404/402/таймаут; у 6,3 % — молча другой сервис
   (godly.website → recent.design, три сервиса → screensdesign.com). Пользователь
   не понимает, ошибся он, устарела статья или сломался сайт. Возврата к списку с отметкой
   «эта не работает» нет; в следующий раз он проверит ту же ссылку заново.

### Эвристики Нильсена — нарушения с severity (0 нет проблемы … 4 катастрофа)

| # | Эвристика | Что нарушено | Sev |
|---|-----------|--------------|-----|
| 1 | **Видимость статуса системы** | Нет статуса актуальности записи и даты проверки; единственная дата — публикация 3-летней давности; `updated_at` скрыт и недостоверен | **4** |
| 2 | **Соответствие системы реальному миру** | Ключевая для аудитории ось «доступно из РФ / есть локальный аналог / чем платить» отсутствует как понятие | **4** |
| 3 | **Свобода и контроль пользователя** | Фильтры не в URL, состояние сбрасывается при возврате из статьи, нельзя расшарить или забукмаркать выдачу, «назад» теряет позицию в ленте | **3** |
| 4 | **Согласованность и стандарты** | Один тип «Дайджест» покрывает новостной обзор, промо-подборку и каталог из 95 ссылок; «раздел» — это на самом деле пресет фильтра | **3** |
| 5 | **Предотвращение ошибок** | Ни валидации ссылок, ни автопроверки доменов, ни пометки о смене владельца сервиса; ошибка обнаруживается только после клика наружу | **4** |
| 6 | **Узнавание вместо припоминания** | Чтобы найти подборки, надо помнить, что они называются «Дайджест»; в меню нет ни «Инструменты», ни «Ресурсы» | **3** |
| 7 | **Гибкость и эффективность** | Нет сортировки по дате обновления, нет фасетов, нет сохранённых фильтров, в поиске вообще нет фильтров | **3** |
| 8 | **Эстетика и минимализм** | Тёмной темы нет («каждый раз глаза вытекают» — UX-патруль); карточка перегружена соц-метриками (5 реакций + 3 счётчика), но лишена практических атрибутов | **2** |
| 9 | **Помощь в распознавании и исправлении ошибок** | Мёртвая внешняя ссылка отдаёт чужой 404; на стороне площадки — ноль обработки, некуда пожаловаться из карточки | **3** |
| 10 | **Справка и документация** | Пустая выдача поиска — тупик: «По вашему запросу ничего не найдено, попробуйте изменить запрос», без подсказок, популярных запросов и кнопки «предложить ресурс» | **3** |

**Что нам с этого:** три из четырёх шагов ломаются на одном и том же — на отсутствии
статуса. Наш минимальный контракт карточки: `последняя проверка: 10.09.2026`,
`статус: работает / изменилось / закрыт`, `из РФ: да / через VPN / нет`,
`аналог: …`, `вердикт куратора: 2–3 фразы`, плюс кнопка «ссылка не работает» прямо в карточке
(закрывает Nielsen #9 и даёт нам поток сигналов для ре-чека). Фильтр обязан жить в URL
и переживать возврат из карточки — это severity 3 у конкурента и бесплатная победа у нас.

## dssign.ru — для сравнения

1. **Что это на самом деле.** Не каталог, а **персональный сайт-портфолио фрилансера**
   на Tilda: `<title>Дизайнер сайтов на Тильде</title>`, description «Eat Sleep Design Repeat»,
   футер «© dssign 2010-2026», об авторе — «20 лет в граф. дизайне… ученый химик (СПбГУ),
   образованный граф. дизайнер (СПбГПУ)». Каталожная часть — ровно **2 страницы из 18**
   в sitemap.xml: `/links` («Топ-50 сервисов для дизайнера в 2025 году») и `/aitools`
   («Топ 7 нейросетей»). Остальное — портфолио, контакты и SEO-статьи-справки
   (что такое dpi, форматы файлов, словарь полиграфических терминов).
2. **Модель контента.** Одна длинная Tilda-страница, **11 рубрик** (Нейросети для дизайнера,
   Приложения, Модификации Тильды, Дизайнерские сервисы, Нейросети для звука, Стоки,
   Рефы и вдохновение, Телеграм-каналы, Обучение дизайну, Что послушать, Боты), внутри —
   57 внешних ссылок. Записи не сущности, а блоки вёрстки: фильтров, тегов, поиска,
   пагинации, карточек-страниц нет вообще. Наполняет один человек; есть UGC-приём
   заявок блоком «Знаешь крутой сервис? Шли!» (35 Tilda-форм на странице).
