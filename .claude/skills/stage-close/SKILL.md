# Закрытие этапа

Закрытие — это не «спасибо, идём дальше», а следы, по которым через неделю видно, что решено
и почему. Решение без записанной причины переоткрывается, и время заказчика тратится дважды.

## Порядок

1. **Проверка по факту.** Прогнать проверки этапа заново (навык `self-check`), а не сослаться
   на прошлый прогон. «Сделано» = «проверено».
2. **Статус.** В `00_pipeline.md` строка этапа: ⏳ → ✅ с датой и номерами решений — `✅ 14.09.2026 (D80–D86)`.
3. **Решения.** Каждое спорное решение — строкой в `docs/DECISIONS.md`, раздел «Решено»:
   номер `D`, решение, причина, дата. Строка в «Предлагаю» не переписывается на месте — в неё
   дописывается «→ перенесено в «Решено» как `Dxx` <дата>», чтобы было видно, как менялся продукт.
   Номер `D` берётся следующий, номер `P` не переиспользуется.
4. **Шапка документа.** У артефакта этапа — «Версия N · утверждена заказчиком <дата>».
   Дальше такой документ правится только по ошибкам: решение заказчика 10.09.2026 —
   «Только исправить ошибки», новое пишется отдельным файлом или следующей версией.
5. **Правило класса.** Если этап закрывался с правкой, которую заказчик назвал словами, —
   это не единичный случай, а класс: правило со способом проверки в `.claude/rules/*.md`
   (если проверяется кодом), слово в `docs/VOICE.md` (если это язык), строка в `DECISIONS.md`
   (если это продуктовое решение). Правило без способа проверки — пожелание.
6. **Память.** Появился факт, который понадобится в следующей сессии (среда, договорённость,
   грабли хостинга) — строка в `MEMORY.md` и файл темы рядом с ним.
7. **Финал.** Вывести блок «Финал» из навыка этапа и **одной строкой предложить следующий шаг**:
   заказчица 11.09.2026 — «добавь потом предложи куда идем дальше».

## Как не потерять файлы

11.09.2026 скрипт закрытия этапа обнулил девять файлов `docs/ia/`: он открыл файл на запись
раньше, чем прочитал его. С тех пор в любом скрипте, который трогает готовые документы:

- читать файл целиком **до** открытия на запись;
- пустой или подозрительно короткий результат не писать вовсе;
- переносы строк сохранять — `open(..., newline="")` и при чтении, и при записи (репозиторий CRLF,
  а `.claude/**` и `.gitignore` — LF);
- после записи — `wc -l` и `git diff --stat`, а не «скрипт отработал без ошибок».

## Проверка

- `grep "⏳" 00_pipeline.md` — нет этапа, закрытого словами, но не в таблице.
- В `docs/DECISIONS.md` нет строки «ждёт ответа» по решению, которое уже принято.
- `git status` показывает только файлы этого этапа; лишнего не зацепило.
- Заказчику отправлен «Финал» и предложен следующий шаг.
