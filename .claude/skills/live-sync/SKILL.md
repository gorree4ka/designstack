# Правка живого сайта

С 14.09.2026 сайт опубликован, и баз стало две: локальная SQLite и MySQL на Beget. Правка в одной
из них — это расхождение, которое обнаружится через неделю на чужом экране. Поэтому изменение
контента пишется **одним файлом** и прогоняется в обоих местах подряд.

## Порядок

1. **Файл правки** — PHP в черновиках сессии, а не команда в консоли: `wp eval` через `tools/wp.cmd`
   идёт по cmd.exe, и `>` `<` `|` `&` `^` превращаются в редиректы (страж `scripts/hooks/wpcli-guard.py`
   такие вызовы блокирует). Файл ищет запись по слагу, а не по номеру: номера в двух базах разные.

   ```php
   $post = get_posts( array( 'name' => 'nazvanie-slaga', 'post_type' => 'post', 'numberposts' => 1 ) );
   // wp_update_post / update_post_meta / wp_update_user — и печать того, что получилось
   ```

   Скрипт печатает результат по каждой записи: id, заголовок, длину, статус, адрес. Молчаливый
   прогон проверить нельзя.

2. **Локально:**

   ```
   tools/wp.cmd --path=wordpress eval-file C:/Temp/.../fix.php
   ```

   Путь — с `C:/`: аргумент, начинающийся со `/`, Git Bash подменяет на путь внутри Git.

3. **На хостинге:** тот же файл уезжает в папку помощников и запускается оттуда:

   ```
   scp fix.php designstack:~/ds-checks/
   ssh designstack "cd ~/designstack/public_html && php8.3 /usr/local/bin/wp-cli.phar eval-file ~/ds-checks/fix.php" \
     | grep -vE "WARNING|post-quantum|Welcome|vulnerable|upgraded"
   ```

   Обёртка `wp` на этом хостинге запускает PHP 7.4 и для WordPress 7 не годится — только
   `php8.3 /usr/local/bin/wp-cli.phar`.

4. **Проверка обеих сторон:**

   ```
   curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/<адрес>/
   curl -s https://designstack.ru/<адрес>/ | grep -o "<title>[^<]*"
   ```

   Плюс `tail -20 wordpress/wp-content/debug.log` локально. Если правка касалась текстов —
   `python scripts/check_voice.py --base https://designstack.ru`.

## Правила

- **Ничего не правим в админке руками** — правка должна воспроизводиться на второй базе.
- **Пароли и коды из чата в файлы не переносятся**, `.env` не читается вообще; заказчица заходит
  в админку сама, сброс пароля — через «Забыли пароль?».
- **Кэш паттернов темы** на хостинге сбрасывается поднятием версии темы, а не `transient delete`:
  у CLI и веб-запроса разные ключи.
- Файл правки остаётся в `~/ds-checks/` — по нему видно, что и когда менялось на живом сайте.
