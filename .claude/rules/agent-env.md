# Правила среды агента

## Навык `.claude/skills/<имя>/SKILL.md`

- Имя папки — латиницей в kebab-case, оно же в поле `name`; папка и поле не расходятся.
- `description` говорит **что делает И когда применять** — это единственный триггер, по которому
  навык поднимается. «Помогает с текстами» не сработает; «Применять, когда нужно переписать
  карточку или вердикт» сработает.
- Файл пишется с переносами **LF**, а `description` и `argument-hint` — **в кавычках**.
  Случай 15.09.2026: при CRLF описание с двоеточием внутри не разбирается, и в списке навыков
  вместо него встаёт первая строка текста — тринадцать навыков из девятнадцати молча остались
  без описания. Способ проверки: после правки навыка список навыков показывает описание, а не
  заголовок.
- Тело — до 500 строк. Больше — справочные таблицы выносятся в соседний файл рядом с `SKILL.md`
  и подключаются ссылкой на один уровень, не глубже.
- Побочные эффекты (деплой, пуш, правка живого сайта) остаются за апрувом заказчика внутри самого
  навыка: «нет апрува — нет действия».

## Субагент `.claude/agents/<имя>.md`

- Только чтение и сбор, задача самодостаточная: субагент не видит переписку и возвращает наверх
  единственный итог.
- Не заводим под интерактив (браузер заказчика, Figma, согласование) и под линейную правку файлов:
  там субагент добавляет задержку, а не пользу.
- Больше двух-трёх одновременно не запускаем: 10.09.2026 веером по пять-семь агентов трижды
  упёрлись в лимит сессии, шестнадцать из двадцати четырёх погибли, не сделав работы.
- Окружение субагента выходит в сеть **не из России** и `WebSearch` там часто недоступен: доступ
  и цены для РФ он не проверяет (навык `ru-check`), факты собирает `curl`-ом.

## Хуки и настройки

- Команда хука в `.claude/settings.json` — только с абсолютным путём: рабочая папка субагента
  плавает, относительный путь молча ломается.
- Вывод хука — `sys.stderr.reconfigure(encoding="utf-8")`, иначе в консоли cp1251 кракозябры.
- Запрет, который должен держаться всегда, — это хук, а не строка в инструкции: `deny` в
  настройках и `PreToolUse`. Инструкция — просьба, хук — гарантия.
- У хука есть тесты в черновиках, и они прогоняются после правки: `scripts/hooks/wpcli-guard.py`
  ловит `> < | & ^` и аргументы, начинающиеся со `/` (Git Bash подменяет их на путь внутри Git).
- Новый файл, записанный скриптом (Python `write_bytes`, `cp`, перенаправление `>`), не проходит защиту
  инструмента записи — тот отказывается перезаписать файл, которого не читал, а скрипт молча затирает.
  Перед тем как дать новому скрипту или документу имя, проверь, что его нет: `ls scripts/ | grep <имя>`.
  Способ проверки — `git diff --stat` перед коммитом: у «нового» файла нет строк с минусом.
  Случай: 28.09.2026 — обход сайта сохранён как `scripts/check_links.py` поверх перепроверки ссылок
  каталога, ушёл в коммит и пуш, возвращён следующим коммитом; обход живёт в `scripts/check_site_links.py`.
- `git checkout -- <файл>` стирает всё, что в этом файле не закоммичено, — включая правки,
  сделанные час назад в этой же сессии. Перед восстановлением файла из гита смотри
  `git diff --stat <файл>`: если строк там больше, чем ты сам сейчас добавил, в файле лежит
  чужая или своя ранняя работа. Выравнивание переносов строк — не повод трогать гит: правь
  байты файла, а не возвращай его версию из индекса. Способ проверки после любого
  восстановления — прогнать по разметке темы и плагина классы `ds-*` и убедиться, что у
  каждого есть правило в CSS. Случай: 15.09.2026 — восстановление `patterns.css` ради
  переносов строк стёрло стили знака в шапке, и логотип уехал на живой сайт в натуральную
  величину и без цвета.
- Инструмент правки файла приводит смешанные переносы к одному виду: в `patterns.css` 289 строк
  с LF посреди CRLF, и правка на 21 строку дала diff на 599. Способ проверки — `git diff --stat <файл>`
  после правки: строк не больше, чем добавлено. Разошлось — `python scripts/fix_eol.py <файл>`
  (совпавшие строки берутся из HEAD побайтно), а не возврат файла из гита. Случай: 30.09.2026, ритм статей.
- `sed -i` в Git Bash переписывает файл целиком с LF: правка одной строки в `style.css` (CRLF) дала в коммите
  все десять строк. Для CRLF-файлов — правка через Python с байтами файла или `scripts/fix_eol.py <файл>` после
  `sed`. Способ проверки тот же — `git diff --stat <файл>` до коммита. Случай: 30.09.2026, версия темы 0.34.0-tables.
