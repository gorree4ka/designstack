# Правила для кода темы и плагинов

Контракт дизайн-системы поставлен этапом 10. Значения токенов — `docs/ds/foundation.md`, их материализация — `theme.json` и `assets/css/theme-dark.css`. Весь контракт проверяет одна команда: `python scripts/check_tokens.py`.

## 1. Кодстайл WordPress

- WordPress Coding Standards: табы, `snake_case`, пробелы внутри скобок `foo( $bar )`, Yoda-условия.
- Все функции и классы темы с префиксом `designstack_` / `DesignStack_`. Никаких глобальных имён без префикса.
- Вывод только через экранирование: `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()`. Ввод — через `sanitize_*`, nonce-проверки, `current_user_can()`.
- Все строки интерфейса — через `__()` / `_e()` / `esc_html__()` с text-domain `designstack`; переводы в `languages/`. Слова берутся из `docs/VOICE.md`.
- Блочная тема (FSE): шаблоны — `templates/*.html`, части — `parts/*.html`, паттерны — `patterns/*.php` с заголовком-комментарием.
- Скрипты и стили подключаем только через `wp_enqueue_*` в хуке `wp_enqueue_scripts` / `enqueue_block_assets`, с версией из `filemtime()`.
- Никаких прямых SQL-запросов; используем `WP_Query`, `get_posts`, `get_option`. Помни: локальная БД — SQLite, MySQL-специфичный SQL не заработает.
- Не редактируем `wp-admin/`, `wp-includes/` и чужие плагины. Изменения только в своей теме и своих плагинах `designstack-*`.
- Новый файл в `patterns/` не появляется на сайте, пока не сброшен кэш: список паттернов темы лежит в сетевом транзиенте `wp_theme_files_patterns-<hash>` и сверяется с версией темы. Сброс — `wp eval-file` с `wp_get_theme()->delete_pattern_cache();` либо `tools/wp.cmd --path=wordpress transient delete --all --network`. У CLI и веб-запроса ключи кэша разные, поэтому проверяй результат `curl`-ом страницы, а не только в CLI. Способ проверки — `curl` страницы: разметка паттерна на месте. Случай: этап 11, 12.09.2026 — 26 новых паттернов молча не рисовались.
- Стиль блока ядра перебивает стиль темы: у `.wp-block-navigation-item__content` специфичность 0,2,0, и правило `.ds-header__nav a` проигрывает — подпись пункта прижималась к верху коробки. Поднимая специфичность, поднимай её во всех связанных правилах: состояние `[aria-current]` и медиазапросы, иначе базовое правило начнёт выигрывать и там, где не должно. Способ проверки — `getComputedStyle` нужного свойства в Playwright и прогон проверки раскладки на границах брейкпоинтов. Случай: этап 11, 12.09.2026 — после правки базового правила шапка снова вылезла на 18 px при окне 900.
- `ref` у блока `core/navigation` — это id записи `wp_navigation`, а не термина классического меню: с id термина блок выводит запись с этим номером. Меню создаёт `scripts/navigation.php`, паттерн шапки ищет запись по слагу `razdely-kataloga` и без неё печатает статический список ссылок. Способ проверки — `curl` шапки: семь пунктов и `aria-label="Разделы каталога"`. Случай: этап 11, 12.09.2026 — в шапке вместо меню вышел текст записи «Sample Page».
- После правки PHP хук автоматически прогоняет `php -l`; после правки шаблонов проверяй страницу через `curl -s http://localhost:8080/...` или скриншот.

## 2. Токены — единственный источник

- Цвет — только семантика: `var(--wp--preset--color--<токен>)`, где токен — строка таблицы «Слой 2» в `docs/ds/foundation.md`: `surface-raised`, `text-muted`, `border-focus-ring`. В атрибутах блоков — тот же slug: `"textColor":"text-muted"`.
- Кегль — `var(--wp--preset--font-size--*)`, шрифт — `var(--wp--preset--font-family--sans)` или `--mono`, отступ — `var(--wp--preset--spacing--*)`, тень — `var(--wp--preset--shadow--md)`. Радиус, межстрочный, трекинг, длительность, z-index и толщина рамки — `var(--wp--custom--*)`.
- Примитивы — `--wp--custom--color--*` и `--wp--custom--shadow--*` — запрещены в CSS паттернов, шаблонах и PHP: они живут только в `theme.json` и `assets/css/theme-dark.css`.
- WordPress отделяет цифры от букв в именах: кегль `2xl` — это переменная `--wp--preset--font-size--2-xl` и класс `has-2-xl-font-size`, ключ `custom.lineHeight.tight` — `--wp--custom--line-height--tight`. Сокращение `var:preset|font-size|…` в `theme.json` WordPress не переводит, поэтому там тоже пишем `2-xl`. Переменная с неверным именем молча не применяется. Способ проверки — `check_tokens.py`, раздел variables: каждая использованная переменная есть на отрисованной странице. Случай: проба этапа 10, 12.09.2026 — `var:preset|font-size|5xl` дал бы несуществующую `--wp--preset--font-size--5xl`.

## 3. Запрет hardcode

- Hex, `rgb()`, `hsl()`, px (кроме условий `@media`, `@container` и `matchMedia()` и значения `0`), имена шрифтов вне `theme.json` — баг. Размер внутри правила — токен: высоты и ширины `--wp--custom--size--*`, толщина рамки `--wp--custom--border-width--*`. Шрифт в CSS — только `var(--wp--preset--font-family--*)` или `inherit`.
- Исключение одно и временное: px-геометрия `assets/css/greybox.css` серого прототипа этапа 08, её заменяют паттерны этапа 11 (D52). `check_tokens.py` считает эти px отдельно; px в любом другом файле — провал.
- Способ проверки — `python scripts/check_tokens.py`, раздел hardcode.

## 4. Нейминг

- Семантика: `surface-*`, `text-*`, `border-*`, `bg-*`, `icon-*`; состояние — суффиксом `-hover`, `-selected`, `-error`. kebab-case, латиница.
- Имена ровно как в `docs/ds/foundation.md`: `surface-action-primary`, не `surfaceActionPrimary` и не `surface_action_primary`. Примитив — `<семейство>-<ступень>`: `gray-500`, `accent-300`.

## 5. Новый токен

- Сначала строка в `docs/ds/foundation.md`: обе колонки, светлая и тёмная, именами примитивов, и пары нового цвета в таблице «Контраст». Затем `theme.json` — alias `var(--wp--custom--color--…)` в палитре. Затем `assets/css/theme-dark.css` — в оба блока.
- Прибитое значение в семантике не принимается: у палитры значение только `var()` на примитив, в палитре нет примитивов.
- Удалять токен можно только после `grep` по теме и плагину, что он нигде не используется.
- Статус каталога заводится тройкой — цвет, иконка Lucide и слово — сразу в `docs/ds/foundation.md` (таблица «Статусы каталога → семантика») и в `docs/VOICE.md`; ключи там и там одни и те же. Статус не показывается одним цветом. Способ проверки — `check_tokens.py`, раздел VOICE.md.

## 6. Тёмная тема

- Новая семантика получает тёмное значение в тот же коммит. Примитивы не переопределяются никогда — только `--wp--preset--color--*` и `--wp--preset--shadow--*`.
- В `theme-dark.css` два одинаковых списка: `:root[data-theme="dark"]` — выбор посетителя, и `@media (prefers-color-scheme: dark)` для `:root:not([data-theme="light"])` — системная тема, когда выбора нет. В обоих `color-scheme: dark`, на `:root` — `color-scheme: light`.
- Цвет, объявленный только внутри `[data-theme]` или media-блока, в третьем состоянии — системная тема без выбора — не применится. Любой цвет сначала объявляется в `theme.json`.
- Файл подключается с зависимостью `global-styles`, иначе встанет раньше инлайновых глобальных стилей и проиграет; в редакторе — без зависимости (`is_admin()`). Инлайн-скрипт выбора темы стоит первым в `wp_head` (приоритет 0), до любого стиля, иначе страница мигнёт светлой. Способ проверки — `curl` главной: скрипт с `designstack-theme` раньше первого `<link rel='stylesheet'>` и `<style>`, а `global-styles-inline-css` раньше `designstack-theme-dark-css`. Случай: проба этапа 10, 12.09.2026.
- Переключатель — кнопка `.ds-theme-toggle` с `aria-pressed` и постоянной подписью «Тёмная тема» из `docs/VOICE.md`; выбор хранится в `localStorage` под ключом `designstack-theme` (`assets/js/theme-toggle.js`).

## 7. Раскладка, шаблоны и формы

- Раскладку проверяй не только на ширинах скриншотов 375 / 768 / 1440, но и на границах CSS-брейкпоинтов 599 / 600, 899 / 900, 1199 / 1200: там ряд, который помещался в середине диапазона, упирается в край. Способ проверки — Playwright на каждой границе, `document.documentElement.scrollWidth` равен ширине окна, у `.header-bar` `scrollWidth` не больше `clientWidth`, ни один элемент `.site-main` и `.site-footer` не заходит правым краем за окно. Случай: grey-box 11.09.2026, шапка шире окна на 3 px при 900 и на 5 px при 1200. Смена шрифта или шкалы кеглей — повод прогнать эти проверки на всех страницах заново: с Golos Text (этап 10, 12.09.2026) шапка вылезла на 11 и 21 px, метка «Открывается из РФ» с `white-space: nowrap` — на 4 px из колонки фактов шириной 106 px, а строка даты и кнопки в карточке перестала помещаться на 1440.
- Ширина из токена — это ширина целиком: у темы стоит общий `box-sizing: border-box`. Без него элемент
  с заданной шириной и полями оказывается шире своей колонки и съедает зазор сетки — колонки слипаются,
  хотя `gap` в CSS правильный. Способ проверки — Playwright: ширина элемента равна ширине трека сетки,
  а расстояние между соседними колонками равно `gap`. Случай: этап 14, 14.09.2026 — панель фильтров
  выходила 314 px в колонке 280 px, зазор 32 px превращался в перекрытие 2 px.
- В constrained-раскладке (`layout: constrained`, класс `is-layout-constrained`) не задавай `max-width` прямому потомку группы: WordPress ставит ему `margin-left/right: auto !important`, и блок уезжает в центр. Ограничивай ширину вложенного элемента (`.topic-intro > p`) или контент-размер самой группы. Способ проверки — скриншот: левый край блока совпадает с левым краем соседей. Случай: описание темы в grey-box 11.09.2026.
- Не задавай `height: 100%` ребёнку элемента сетки или списка (`li > a` в grid): процент может посчитаться не от строки сетки, и плитка наедет на соседний ряд. Растягивай через flex: родитель `display: flex`, ребёнок `flex: 1`. Способ проверки — Playwright: у соседних плиток, карточек и шагов прямоугольники `getBoundingClientRect()` не пересекаются; `scrollWidth` и равная высота рядов такое наложение не ловят. Случай: входы в разделы на главной, grey-box 11.09.2026, 375 и 768 px.
- Компонент, который стоит в списках разной ширины (`resource-card`: сетка раздела, колонка шага на главной, телефон), перестраивает свои части по ширине своего контейнера — `container-type: inline-size` и `@container`, — а не по ширине окна: одна и та же ширина окна даёт карточки от 266 до 437 px. `@container` меряет содержимое без полей и рамки: при полях 16 и рамке 1 запрос `max-width: 359px` срабатывает в карточке уже 394 px, а не 360 — порог в решении называй вместе с тем, что он меряет. Способ проверки — Playwright в каждом списке, где стоит компонент, на ширинах скриншотов, границах брейкпоинтов и окнах, где карточка пересекает порог: расположение частей совпадает с порогом, части не пересекаются, обрезанных названий нет. Случай: бейдж типа съедал строку названия в колонке шага на главной, grey-box 11.09.2026 (D44).
- Стандартные типы шаблонов блочной темы (`single`, `page`, `index`, `archive` и другие из `get_default_block_template_types()`) не назначаются записи или странице: у них `is_custom` = no, в списке назначаемых шаблонов их нет. Раскладку, которая живёт в таком шаблоне, показывай записью нужного типа — WordPress сам возьмёт шаблон по иерархии; вариант раскладки для части записей одного типа (подборка и выпуск на одном `single.html`) — пользовательский шаблон записи с `postTypes: ["post"]` или условие по категории. Способ проверки — `wp eval-file` с `get_block_template( get_stylesheet() . '//<slug>' )->is_custom` и `wp_get_theme()->get_page_templates( null, 'post' )`. Случай: заглушки партии 3 «Редакция», grey-box 11.09.2026.
- Имя шаблона страницы в мете `_wp_page_template` пишется без расширения: у блочной темы валидный
  слаг — `page-about`, а не `page-about.html`. С неверным значением `wp_update_post()` отбивает любую
  правку страницы сообщением «Неверный шаблон страницы», причём в редакторе страница открывается
  нормально, и дефект всплывает только при программном обновлении. Способ проверки — сверить мету
  всех страниц со списком `wp_get_theme()->get_page_templates( $post, 'page' )`. Случай: 15.09.2026 —
  «О проекте» и «Предложить ресурс» не обновлялись ни локально, ни на хостинге.
- Обратная сторона того же: код, который сравнивает шаблон страницы с именем, сравнивает со слагом без
  расширения — для этого есть `designstack_is_template( 'page-suggest' )`. Сравнение с `page-suggest.html`
  не срабатывает молча: блок из шаблона рисуется, а его скрипт не подключается, и в консоли пусто.
  Способ проверки — `curl` страницы и поиск имени скрипта в ответе. Случай: 15.09.2026 — `form.js`
  не подключался на «Предложить ресурс» с этапа 14, форма работала без подсветки ошибок.
- Имена полей формы, которая отправляется на страницу WordPress, не совпадают с публичными query vars: `WP::parse_request()` читает их не только из адреса, но и из тела POST, и отправка открывает 404 или чужую выдачу. В ядре WordPress 7.1 их 51 — среди них `name`, `s`, `p`, `m`, `page`, `author`, `year`, `cat`, `tag`, `order`, `error`, `embed`; плагин добавит свои — таксономию `topic` и ключи фильтров. Поле называй по смыслу с уточнением: `resource_name`, а не `name`. Способ проверки — `wp eval-file` со списком `apply_filters( 'query_vars', $wp->public_query_vars )` против имён полей формы и POST-проба на адрес, куда уходит форма: ответ не 404. Случай: форма «Предложить ресурс», grey-box 11.09.2026 — POST с полем `name` на `/suggest/thanks/` ответил 404, с `resource_name` — 200.

## 8. Плагин: данные, блоки и адреса

- Поле-список хранится отдельными строками meta (`register_post_meta` с `single => false`), а не сериализованным
  массивом: по сериализованному `meta_query` не находит ничего, хотя в REST обе формы выглядят массивом. Это
  касается всех полей, по которым есть или будет фильтр. Способ проверки — `get_posts` с `meta_query` по одному
  значению списка: находит запись. Случай: этап 12, 12.09.2026, проба `meta-array-schema` (D64).
- Рядом с `editor.js` блока обязателен `editor.asset.php`, возвращающий массив зависимостей (`wp-blocks`,
  `wp-element`, `wp-components`, `wp-block-editor`, `wp-server-side-render`, `wp-i18n`). Без него `editorScript`
  регистрируется без зависимостей, скрипт выполняется раньше `wp.blocks`, и блока просто нет в реестре редактора —
  ошибки в консоли при этом не видно. Способ проверки — в редакторе `wp.blocks.getBlockType('<имя>')` возвращает
  объект. Случай: этап 12, 12.09.2026, проба `dynamic-block-no-build` (D63).
- В `render.php` блока нельзя объявлять функции: файл подключается на каждый рендер, и второй вызов роняет PHP
  с `Cannot redeclare`. Общие функции — в `includes/`. Способ проверки — отрисовать блок дважды за один запрос
  (`do_blocks` плюс маршрут `/wp/v2/block-renderer/…`). Случай: этап 12, 12.09.2026, блок `suggest-form`.
- `meta_box_cb` у таксономии с `show_in_rest` в блочном редакторе не работает: WordPress рисует свою панель, а
  классический метабокс не показывает. Значение выбранного терма скрипт берёт из хранилища редактора
  (`wp.data.select('core/editor').getEditedPostAttribute('<таксономия>')` — там номера термов, не слаги), карту
  «номер → слаг» передаём через `wp_localize_script`. Способ проверки — Playwright: при смене типа в панели
  редактора нужный fieldset становится видимым, чужие — `hidden`. Случай: этап 12, 12.09.2026, панель полей ресурса.
- Смена `post_status` внутри `save_post` стирает слаг записи, если не передать `post_name` явно: WordPress
  пересобирает его и для непубличного статуса делает пустым, а потом слаг собирается заново из русского названия.
  Способ проверки — `wp post list --field=post_name` после сохранения. Случай: этап 12, 12.09.2026 — страж
  публикации D32 обнулил слаги всех записей наполнения.
- `wp_http_validate_url()` делает DNS-запрос и отбивает домены, которые не резолвятся с сервера. Для проверки
  адреса, введённого человеком, она не годится — берём `filter_var( $url, FILTER_VALIDATE_URL )` плюс проверку
  схемы. Способ проверки — POST формы с адресом несуществующего домена: ответ не «это не похоже на адрес сайта».
  Случай: этап 12, 12.09.2026, форма «Предложить ресурс».
- Адрес, которому положено отвечать 404, ядро всё равно пытается угадать: `redirect_canonical()` ищет запись по
  началу слага и уводит 301 на чужую страницу. Гасится фильтрами `do_redirect_guess_404_permalink` и
  `redirect_canonical` для нужных путей, одного `$wp_query->set_404()` мало. Способ проверки — `curl -o /dev/null
  -w "%{http_code} %{redirect_url}"`. Случай: этап 12, 12.09.2026 — `/resource/` уводил на страницу серого
  прототипа `resource-figma` (D65).

## 9. Сборка страниц из блоков

- Паттерны этапа 11 — витринные листы: в файле лежат все варианты сразу (`ds-stack` с тремя заголовками, четырьмя
  уведомлениями). Вставлять их в шаблон нельзя — страница соберёт все варианты подряд. В шаблон идут core-блоки
  с классами паттерна и блоки плагина; вставляемых паттернов всего четыре: `entry-tiles`, `subscribe-cta`,
  `collection-group`, `issue-find`. Способ проверки — открыть `patterns/<slug>.php`: если внутри `ds-stack`
  с несколькими образцами, это витрина. Случай: этап 13, 12.09.2026, партия 1.
- Ширина контента в шаблоне задаётся `"align":"wide"` у группы, а не `contentSize` в пикселях: пиксель в шаблоне —
  это хардкод, который переживёт смену токенов. Способ проверки — `python scripts/check_tokens.py` и
  `grep -rnE "[0-9]+px" templates/`. Случай: этап 13, 12.09.2026 — `contentSize: 1360px` в трёх шаблонах.
- Порядок блоков в разметке — это порядок на телефоне. Колонки раскладывает `grid-template-areas` от 900,
  поэтому в разметку кладём мобильный порядок (шапка → факты → оценка), а не десктопный. Способ проверки —
  скриншот 375: порядок секций совпадает с карточкой страницы. Случай: этап 13, 12.09.2026 — на странице ресурса
  факты оказались после оценки.
- `core/breadcrumbs` рисует свой разделитель через `--separator` в инлайн-стиле. Если разделитель есть и у паттерна,
  на странице их два: «Главная / › Инструменты». Гасится в фильтре `render_block_core/breadcrumbs`. Способ проверки —
  `curl <адрес> | grep -o "separator: [^\"]*"`. Случай: этап 13, 12.09.2026.
- `core/navigation-link` отмечает пункт текущим только для связанной записи или архива типа записей. Пользовательская
  ссылка (`/tools/`, `/collections/`) текущей не станет — это делает тема фильтром `render_block_core/navigation-link`,
  и раздел остаётся текущим на своих записях тоже. Способ проверки — `curl /tools/ | grep aria-current` находит
  `aria-current="page"` у ссылки меню, а не только в крошках. Случай: этап 13, 12.09.2026.
- Разделитель «·» между значениями склеивается с предыдущим словом неразрывным пробелом, иначе при переносе он
  уезжает в начало следующей строки и висит там один. В коде — один хелпер `designstack_core_join()`.
  Способ проверки — `grep -rn "' · '" wordpress/wp-content/plugins` пусто. Случай: этап 13, 12.09.2026, факты Figma.
- Пустая выдача убирает не только сетку: панель фильтров, чипсы и пагинация тоже не выводятся — фильтровать нечего.
  Способ проверки — на пустом архиве в разметке нет `ds-filters`, `ds-chips`, `ds-pagination`. Случай: этап 13,
  12.09.2026, `/topic/accessibility/`.

- Цепочка `команда && команда` обрывается на первой ошибке: если после `&&` дописывалась CSS или файл,
  её там не окажется, а страница просто отрисуется без стилей. Способ проверки — после дозаписи в файл
  `grep` по добавленному классу в самом файле, а не по выводу команды. Случай: этап 13, 12.09.2026 —
  `.ds-prose` и `.ds-issue-nav` не попали в `patterns.css`, текст записи поехал на всю ширину.
- Встроенный поиск WordPress возвращает и страницы, а не только записи каталога. Если рендер выводит
  не все типы, число найденного не сойдётся с числом карточек. Способ проверки — на выдаче число в строке
  равно числу `article` в разметке. Случай: этап 13, 12.09.2026 — «3 результата» при одной карточке.
- Служебная страница (витрина) в выдаче поиска не нужна: она noindex и её нет в карте сайта. Убирается
  `pre_get_posts` только для поиска. Способ проверки — `curl "/search/?s=…" | grep styleguide` пусто.
  Случай: этап 13, 12.09.2026.

## 10. Оживление: выборка, формы, состояния

- Публичная таксономия фильтрует сама: у неё есть переменная запроса, и `?topic=prototyping` сужает выдачу
  до того, как написана хоть строка фильтров. Свой `tax_query` поверх — это второе такое же условие.
  Способ проверки — до кода открыть архив с параметром и посчитать карточки. Случай: этап 14, 14.09.2026.
  Закрытая таксономия (`public => false`) наоборот не фильтрует вовсе — её добавляем руками.
- Встроенная проверка браузера (`required`, `type="url"`) перехватывает отправку раньше сервера, и серверные
  состояния формы становятся недостижимы, а человек видит два разных вида ошибок. Если ошибки рисует сервер
  в своём оформлении — у формы стоит `novalidate`. Способ проверки — отправить пустую форму: возвращается
  своя сводка, а не пузырёк браузера. Случай: этап 14, 14.09.2026, форма «Предложить ресурс».
- `history.replaceState()` не пересчитывает `:target`: панель, раскрытая якорем, после смены адреса останется
  раскрытой. Со скриптом состоянием управляет атрибут (`data-ds-open`), а якорь остаётся запасным путём без JS.
  Способ проверки — Escape закрывает панель на 375. Случай: этап 14, 14.09.2026, панель фильтров.
- Фокус, поставленный до `load`, сбивается переходом браузера по якорю адреса: `#ds-suggest-form` в адресе
  возврата уводил фокус с сводки ошибок. Ставим фокус в обработчике `load`. Способ проверки — Playwright:
  после возврата с ошибками `document.activeElement` — сводка. Случай: этап 14, 14.09.2026.
- Раскрытая панель шапки без JavaScript накрывает страницу: `position: absolute` у выпадающего меню имеет смысл
  только там, где его умеют закрыть. Абсолютное позиционирование вешаем на класс, который ставит скрипт.
  Способ проверки — Playwright с `java_script_enabled=False`: клик по элементу под шапкой не перехватывается.
  Случай: этап 14, 14.09.2026.
- Атрибут `hidden` проигрывает любому селектору с `display`. Скрипт прячет шаг, вопрос или
  панель через `el.hidden = true`, а правило вроде `.ds-quiz__list > li { display: flex }`
  или `.ds-button { display: inline-flex }` перебивает браузерное `[hidden] { display: none }`
  по специфичности — и на экране разом видно всё, что должно быть скрыто. Лечится сужением
  селектора до `:not([hidden])` либо явным `display: none` для `[hidden]` внутри блока.
  Способ проверки — Playwright: число элементов с `offsetParent !== null` совпадает с числом
  элементов без атрибута `hidden`; проверять по вычисленному стилю, а не по разметке.
  Случай: проверка грейда 15.09.2026 (кнопки шага) и тренажёр урока 16.09.2026 (все десять
  вопросов показались сразу).
- Значения фильтра в панели и значения в выборке должны браться из одного места. Пока панель строила список
  своим кодом, формат файла показывался как «OTF», а в записи лежал слаг «otf» — совпадение держалось на
  регистронезависимом сравнении SQLite и на MySQL могло пропасть. Способ проверки — `grep` по коду: список
  значений оси собирается одной функцией. Случай: этап 14, 14.09.2026.
- Базовая цена страницы этой темы — 25–26 запросов даже там, где нет данных (меню, части шаблона, глобальные
  стили). Цель «карточка ≤ 20 запросов» ею съедена; мерить надо прирост над базой, а не общее число.
  Способ проверки — счётчик `get_num_queries()` на пустой текстовой странице и на нужной. Случай: этап 14,
  14.09.2026 — архив 29, страница ресурса 29, подборка 41.

- Уровень заголовка карточки задаёт место на странице, а не привычка. Одинаковый `<h3>` во всех списках
  даёт пропуск уровня там, где карточка идёт сразу под H1: структура страницы для чтеца и поисковика рвётся.
  Уровень передаётся параметром, а для списков в содержимом записи считается от последнего заголовка,
  который страница уже напечатала (`designstack_core_heading_level()`, фильтр `render_block`).
  Способ проверки — выписать заголовки внутри `#ds-main` по порядку: разница между соседними ≤ 1.
  Случай: этап 15, 14.09.2026 — 13 страниц с прыжком H1 → H3.
- Цветной текст на подкрашенной плашке не добирает 4,5:1. Пометка вроде «подсказка» на
  `bg-error` цветом `text-error` даёт 4,26:1, а «зачем» на `surface-selected` цветом
  `text-action` — 4,45:1: обе пары выглядят контрастными и обе не проходят. Правило: смысл
  несёт плашка и слово, а сам текст пишется `text-default` — это 12–15:1 в обеих темах.
  Способ проверки — `python scripts/audit_a11y.py` по обеим темам: ноль нарушений
  `color-contrast`. Случай: аудит 16.09.2026, пометки в трёх уроках, светлая и тёмная темы.
- `<th>` без `scope` и `<label for>` вокруг своего же поля — невалидная разметка, которую
  глаз не ловит. Заголовок колонки всегда `<th scope="col">`; если поле лежит внутри метки,
  атрибут `for` из неё убирается. Осторожно с заменой по регулярке: `<th` совпадает и с
  `<thead`, и получается `<thead scope="col">`. Способ проверки — `npx html-validate@8` по
  сохранённым страницам: правила `wcag/h63` и `no-redundant-for` пусты. Случай: аудит
  16.09.2026 — 43 заголовка таблиц в уроках и 185 меток в проверке грейда.
- Заголовок вкладки длиннее 70 знаков обрезается в выдаче. У типа записи, где заголовок
  читается как фраза (урок), `<title>` собирается коротким из полей — «навык · ступень», —
  а длинный остаётся на странице. Способ проверки — `npx html-validate@8`, правило
  `long-title`. Случай: аудит 16.09.2026, три страницы уроков.
- Заголовок обёртки — `div`, не `span`: `<span>` по спецификации несёт фразовое содержимое, заголовок в нём
  невалиден, и браузер его отрисует, а валидатор поймает только на аудите. Способ проверки —
  `npx html-validate@8` по сохранённой странице: правило `element-permitted-content`.
  Случай: этап 15, 14.09.2026 — 92 случая в карточках.
- Неактивный элемент нельзя гасить одной `opacity`: исключение WCAG для неактивных контролов действует на
  настоящие контролы, а `<span class="is-disabled">` в пагинации им не является, и 4,5:1 с него спрашивают.
  Гасим токенами — подложка `surface-subtle`, подпись `text-muted`. То же и с наведением: подпись идёт
  ступенью следом за подложкой, иначе акцент тонет (в тёмной теме давал 4,22:1).
  Способ проверки — axe по обеим темам, витрина показывает состояния статикой. Случай: этап 15, 14.09.2026.
- Заголовок вкладки берётся из той же карты разделов, что H1 и крошки (`document_title_parts`), а подписи
  служебных страниц ядра приводятся к словарю в `block_core_breadcrumbs_items`. Иначе одна страница зовётся
  двумя способами: «Инструмент» во вкладке и «Инструменты» в заголовке, «Результаты поиска для "figma"»
  в крошке и «Поиск» на странице. Способ проверки — сверить `<title>`, H1 и последнюю крошку.
  Случай: этап 15, 14.09.2026.
- Новый файл паттерна не появляется, пока жив кеш списка паттернов темы: `WP_Theme::get_block_patterns()`
  держит его в site-транзиенте `wp_theme_files_patterns-<hash>` до смены версии темы. Симптом — вставка
  `wp:pattern` молча не выводит ничего. Способ проверки — `delete_site_transient()` и повторный `curl`;
  на хостинге проще поднять версию темы. Случай: этап 15, 14.09.2026.

- Инлайновый разделитель внутри flex-колонки повисает отдельной строкой: каждый ребёнок такого
  контейнера — самостоятельный flex-элемент, и неразрывный пробел его не спасает. Список ссылок
  через «·» отдаём одним элементом (`<span>`), а не набором соседей. Способ проверки — посчитать
  `getClientRects().length` у строки значения: больше одной прямоугольной области при коротком
  списке значит, что разделитель оторвался. Случай: этап 16, 14.09.2026 — строка «Темы» в фактах
  ресурса выводилась тремя строками на всех сорока страницах с этапа 13.

- Обещание в подписи секции должно быть условием выборки, а не пожеланием. «Бесплатные и с бесплатным
  тарифом, все проверены куратором» под стартовым набором ничего не проверяло: выборка шла только по теме
  и грейду. На демо-данных это не всплыло — там все записи были открыты и бесплатны; на живом каталоге в
  набор для новичка попал ресурс, закрытый для России. Способ проверки — прочитать подпись секции и
  сверить каждое её утверждение с `meta_query` запроса. Случай: этап 16, 14.09.2026 — Uizard (`ru_open =
  blocked`) в шаге «Прототип» первого экрана.

- У записи `post` обязателен свой `post_excerpt`. Шапка страницы (`ds-page-header__lead`) при пустом
  поле берёт автоотрывок — первые 55 слов содержимого, — и читатель видит первый абзац дважды подряд:
  в лиде с многоточием и сразу под ним целиком. На демо-записях этапа 12 дефект не всплыл, потому что
  сид проставлял отрывок руками. Способ проверки — `post list --post_type=post --field=ID` и по каждой
  `post get <id> --field=post_excerpt`: пустых быть не должно. Случай: этап 16, 14.09.2026 — первая
  настоящая подборка.

- Текст вердикта не должен противоречить проверенному полю. Вердикт пишется словами и живёт дольше
  поля: поле обновили прогоном, фразу забыли. Способ проверки — прогнать по каталогу
  `preg_match('/VPN|из России|с российского|не открыва|блокир|не всегда/iu', $verdict)` и сверить
  каждое совпадение с `ru_open` и `ru_payment` записи. Случай: этап 16, 14.09.2026 — у Miro поле стало
  `open` решением D94, а вердикт остался «из России открывается не всегда».

- Новое значение перечисления доходит до панели фильтров только вместе с осью. Метка на карточке
  рисуется по `designstack_core_enums()`, а панель показывает ось, лишь если она перечислена для
  этого раздела в `designstack_core_filter_groups()`: добавив значение, легко получить карточку
  с меткой, по которой раздел не умеет отбирать. Способ проверки — по каждому разделу сравнить
  метки в выдаче (`grep 'ds-badge'`) с легендами панели (`grep 'ds-filters__legend'`): метка без
  своей оси — баг. Случай: этап 16, 14.09.2026 — значение `unstable` появилось у записи «Учёбы»,
  а оси «Доступ из РФ» в этом разделе не было.

- Группа фильтров с одним вариантом не выводится, но флажок — выводится. Один вариант в группе
  выбора ничего не отсеивает и обещает работу, которой не делает (продолжение D85); у оси-флажка
  вроде «Есть вакансии» значение одно по природе, и снятый флажок значит «неважно». Список таких
  осей — `designstack_core_toggle_axes()`. Способ проверки — открыть все четыре раздела и убедиться,
  что в каждой группе либо два и больше вариантов, либо она объявлена флажком. Случай: этап 16,
  14.09.2026 — правило «меньше двух вариантов — не показываем» сняло «Есть вакансии» в «Сообществах».

- Хук на `save_post`, который меняет статус записи, должен молчать при импорте. Импорт создаёт
  запись раньше её мета-полей, поэтому любая проверка «поле заполнено?» на импорте провалится:
  страж публикации D32 отправил на утверждение все 140 записей каталога и обнулил им слаги.
  Условие — `defined( 'WP_IMPORTING' ) && WP_IMPORTING`. Способ проверки — после `wp import`
  сравнить число записей в статусе `publish` с числом в выгрузке и убедиться, что `post_name`
  не пуст. Случай: этап 19, 14.09.2026, перенос на хостинг.
