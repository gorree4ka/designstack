# designstack-core

Модель данных каталога DesignStack: тип записи «Ресурс», таксономии, поля, блоки и форма «Предложить ресурс».
Данные живут здесь, а не в теме: смена темы не теряет ни полей, ни адресов.

Собран этапом 12 конвейера (`12_directive_core_plugin.md`). Источник требований — `docs/brief.md` §5 и §7,
`docs/spec.md` (US-42, US-47), карта адресов `docs/ia/sitemap.md` («Требования к 12»), разметка —
`docs/ds/components.md` («Контракт разметки для этапа 12»), слова — `docs/VOICE.md`.

## Структура

```
designstack-core.php     заголовок, константы, подключение файлов, активация
includes/enums.php       справочники значений и реестр полей — один источник правды
includes/post-types.php  тип записи resource
includes/taxonomies.php  resource_type, topic, level, skill; термы словаря при активации
includes/meta.php        register_post_meta, санитизация, чтение и запись полей, D32
includes/rewrite.php     короткие адреса разделов, рубрики, поиск, редиректы и 404
includes/render.php      разметка каталога: карточка, метки, факты, пустое состояние
includes/blocks.php      регистрация блоков и справочники для их панелей
includes/form.php        приём формы «Предложить ресурс»
admin/meta-box.php       панель «Поля ресурса» в редакторе
admin/meta-box.js        показ полей по выбранному типу
admin/columns.php        колонки списка записей: доступ, оплата, состояние, дата проверки
blocks/<имя>/            block.json, render.php, editor.js, editor.asset.php
uninstall.php            удаление настроек; записи и термы остаются
```

Префикс функций — `designstack_core_`, text-domain — `designstack-core`, требуется PHP 8.3.

## Модель данных

Один тип записи `resource`, вид задаёт таксономия `resource_type` (решение D59). Поля, специфичные для
типа, показываются в редакторе условно, а на странице ресурса выводятся только заполненные.

**Ключ поля — якорь.** Имя в brief §5.1 = ключ meta в базе = поле в REST = атрибут блока. Переименование —
только через бриф.

| Ключ | Группа | Подпись | Хранение | Значения |
|---|---|---|---|---|
| `url` | Общие | Адрес ресурса | одно значение, string | адрес |
| `verdict` | Общие | Вердикт | одно значение, string | строка до 120 знаков |
| `review_for` | Общие | Кому подходит | одно значение, string | свободный текст |
| `review_why` | Общие | За что | одно значение, string | свободный текст |
| `review_not` | Общие | Когда не подойдёт | одно значение, string | свободный текст |
| `pricing` | Общие | Цена | одно значение, string | `free` · `freemium` · `paid` · `trial` |
| `price_note` | Общие | Заметка о цене | одно значение, string | свободный текст |
| `ru_open` | Общие | Доступ из РФ | одно значение, string | `open` · `vpn_only` · `blocked` |
| `ru_payment` | Общие | Оплата из РФ | одно значение, string | `payable` · `intermediary` · `no_payment` · `ru_native` |
| `ru_alternative` | Общие | Аналог из России | список, отдельные строки meta | номера записей `resource` |
| `language` | Общие | Язык | одно значение, string | `ru` · `en` · `multi` |

| `platforms` | Инструмент | Платформы | список, отдельные строки meta | `web` · `mac` · `win` · `ios` · `android` · `figma-plugin` |

| `skill_middle` | Учебный материал | Поднимает навык до middle | список, отдельные строки meta | номера термов `skill` |
| `skill_senior` | Учебный материал | Поднимает навык до senior | список, отдельные строки meta | номера термов `skill` |
| `license` | Ассет | Лицензия | одно значение, string | `free-commercial` · `personal-only` · `cc-by` · `paid` |
| `file_format` | Ассет | Формат файла | список, отдельные строки meta | слаги: `figma`, `svg`, `otf` … |

| `audience_size` | Сообщество | Размер аудитории | одно значение, string | оценка с датой: «≈ 12 000, 09.2026» |

| `is_jobs` | Сообщество | Вакансии | одно значение, boolean | да / нет |

Всего 31 поле, все со схемой REST, `sanitize_callback` и `auth_callback`. Плюс два служебных, скрытых из
REST: `_designstack_seed` (демо-запись) и `_designstack_suggested_by` (обратная почта из формы).

Чего в полях нет намеренно:

- **куратор** — это автор записи (`post_author`), выводится именем и ролью;
- **грейд** — таксономия `level`, а не поле;
- **навык** — таксономия `skill`; уровень, до которого материал поднимает навык, лежит в трёх полях
  `skill_*` (D62): такое поле отбирается штатным `meta_query`, а один список пар — нет.

Значение enum вне справочника заменяется пустым: врать меткой хуже, чем её не показать.
У бесплатного ресурса поле оплаты не заполняется и метки оплаты нет (D28).
Ресурс без части оценки «Когда не подойдёт» не публикуется: публикация возвращает запись на утверждение
и показывает куратору сообщение (D32).

## Таксономии и адреса

| Таксономия | Вид | Термы | Адрес |
|---|---|---|---|
| `resource_type` | плоская, один терм на запись | `tool`, `learning`, `asset`, `community` | `/tools/`, `/learn/`, `/assets/`, `/community/` |
| `topic` | иерархическая | 12 тем из brief §5.1 | `/topic/{slug}/` без третьего уровня |
| `level` | плоская, без публичного архива | `junior`, `middle`, `senior` | параметр фильтра `?level=` |
| `skill` | иерархическая, без публичного архива | заводит этап 16 | только редактор и REST |

Термы `resource_type`, `topic`, `level` и рубрики `collections` / `digest` / `reviews` создаются при
активации, если их нет.

| Адрес | Ответ |
|---|---|
| `/tools/`, `/learn/`, `/assets/`, `/community/` и `…/page/N/` | 200, архив типа |
| `/topic/{slug}/` | 200 |
| `/resource/{slug}/` | 200 |
| `/collections/`, `/digest/`, `/reviews/` и `/{раздел}/{slug}/` | 200 |
| `/search/?s=…` | 200 |
| `/resource_type/{slug}/`, `/category/{slug}/`, `/author/*`, `/?s=`, `/?topic=` | 301 на канонический адрес |
| `/resource/`, `/level/*`, `/skill/*`, `/tag/*`, архивы дат, `page/N/` за пределами | 404 |

Адрес записи включает раздел, поэтому при активации ставится структура ссылок `/%category%/%postname%/`
(решение OQ-02 а карты адресов). У записи ровно одна рубрика из трёх — лишние снимаются на сохранении.

`/resource/` отвечает 404 принудительно: иначе ядро угадывает запись по началу слага и уводит 301 на чужой
адрес (D65). Правила адресов обновляются только при активации и деактивации; после правок вручную —
`tools/wp.cmd --path=wordpress rewrite flush`.

## Блоки

Все четыре — серверный рендер без сборки: `block.json` с `"render": "file:./render.php"`, редактор на
обычном JS. Рядом с `editor.js` обязателен `editor.asset.php` со списком зависимостей: без него блок молча
не попадает в реестр редактора (D63).

| Блок | Что делает | Атрибуты |
|---|---|---|
| `designstack/resource-list` | карточки: выбранные вручную или отобранные | `ids`, `resource_type`, `topic`, `level`, `pricing`, `ru_open`, `ru_payment`, `limit` 6–24, `layout` grid/list, `orderby` checked_at/date/title |
| `designstack/resource-meta` | факты текущего ресурса списком | `fields`, `showTopics` |
| `designstack/ru-status` | метки доступа и оплаты, состояние, дата проверки | `showChecked`, `showState` |
| `designstack/suggest-form` | форма «Предложить ресурс» | `preview` — состояние для просмотра в редакторе |

Разметка повторяет паттерны темы: `ds-card`, `ds-badge`, `ds-badges`, `ds-facts`, `ds-empty`, `ds-notice`,
`ds-field`, `ds-error-summary`, `ds-suggest-form`. CSS — в теме (`assets/css/patterns.css`), здесь его нет.
Иконки берутся из спрайта темы через `designstack_icon()`, если тема DesignStack на месте; без неё метка
остаётся словом — статус читается и без иконки.

## Форма «Предложить ресурс»

Работает без регистрации. Поля: адрес (обязательно), название, комментарий, почта, согласие (обязательно).
Обработчик — `admin_post_nopriv_designstack_suggest` и `admin_post_designstack_suggest`.

- nonce обязателен; без него — состояние «сбой отправки», записи нет;
- поле-ловушка `resource_site` скрыто классом темы: заполнено — посетитель видит успех, записи нет;
- лимит 3 отправки в час с одного подключения; в ключ транзиента идёт хеш адреса, сам адрес не сохраняется;
- адрес, который уже есть в каталоге, даёт состояние «уже есть» со ссылкой на страницу ресурса;
- годная отправка создаёт запись `resource` со статусом «на утверждении», комментарий кладётся в тело
  записи, обратная почта — в `_designstack_suggested_by`;
- письмо куратору уходит на `admin_email`; неудача письма не считается сбоем отправки — факт пишется
  в `debug.log` (D66). Локально на `php -S` письмо не уходит: `wp_mail` отбивает адрес отправителя
  `wordpress@localhost`.

Вид адреса проверяется без DNS (`filter_var` + схема http/https): `wp_http_validate_url()` делает
DNS-запрос и отбивает домены, которые не резолвятся с сервера, — а каталог собирает и заблокированные сайты.

Состояния вывода: по умолчанию · ошибки полей со сводкой «Проверь форму» · сбой отправки · лимит ·
«уже есть в каталоге». Успех живёт на отдельной странице `/suggest/thanks/`.

## Демо-контент

```
python scripts/seed.py           наполнить или обновить
python scripts/seed.py --check   проверить данные, ничего не записывая
python scripts/seed.py --reset   удалить записи с меткой _designstack_seed
```

Данные — `scripts/seed_data.json`, редактируется руками. 28 ресурсов по 7 на тип, 2 подборки и 1 выпуск
дайджеста с блоком списка ресурсов. Перед записью данные проверяются на покрытие: все значения цены,
доступа, оплаты и состояния, бесплатный ресурс без поля оплаты, свежая и просроченная даты проверки,
длинное название, пустая тема «Доступность» и аналог у закрытого ресурса.

Идемпотентно: запись ищется по слагу, существующая обновляется. Второй прогон подряд создаёт ноль записей.

Значения `ru_open` и `ru_payment` в демо поставлены по открытым данным и **не являются** проверкой
с российского IP (O8) — настоящие проверки делает этап 16.

Отличия от плана директивы: тяжёлую часть выполняет `scripts/seed.php` одним вызовом `wp eval-file`, а не
сотнями команд `wp post meta update` — на Windows каждый вызов WP-CLI стоит около полусекунды. Запись идёт
функциями плагина, то есть через ту же санитизацию, что и правки в редакторе. `--reset` не удаляет рубрики:
они часть структуры адресов, а не контента, и создаются при активации.

## Ограничения

- Локально база SQLite; на продакшене MySQL 8. Прямых запросов SQL в плагине нет, `meta_query` проверен
  пробой на SQLite (D63).
- Фильтрация, поиск по полям и пагинация архивов — этап 14: плагин регистрирует имена параметров
  (`pricing`, `ru_open`, `ru_payment`, `platforms`, `format`, `language`, `license`, `file_format`,
  `cyrillic`, `platform`, `is_jobs`, `level`) и отдаёт данные, но выборку по ним не строит.
- Блоки пока не стоят на публичных страницах: шаблоны серого прототипа этапа 08 не выводят содержимое
  записи. Страницы собирает этап 13.
- Логотип ресурса в карточке — буква-заглушка, как в каталоге паттернов; картинки логотипов ставит этап 16.
- Размер метки в блоке `ru-status` один: класса под второй размер в каталоге паттернов нет, и мы его
  не заводим.
