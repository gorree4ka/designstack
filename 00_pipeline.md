# Конвейер DesignStack: карта директив

> Версия 2.0 от 10.09.2026. Конвейер переработан из «приложение + Figma + React» в «сайт-каталог на WordPress, прототип сразу в коде на локальном сервере». Исходные директивы v1 лежат в `_archive/directives_v1/`.
> Запуск любой директивы: `/directive NN` или «выполни директиву NN». Идём поэтапно: одна директива — один этап — апрув — следующая.

## Что строим

Русскоязычный живой каталог ресурсов для UX/UI/продуктовых дизайнеров (см. `docs/brief.md`, утверждён 10.09.2026). Стек: WordPress 7.x, PHP 8.3, блочная тема `designstack`, плагин `designstack-core` (post type `resource`, 4 типа, таксономии, поля), локально SQLite + `php -S`, продакшен — российский хостинг с MySQL. Figma в основном пути не используется: прототип, дизайн-система и страницы собираются сразу в коде и проверяются на `http://localhost:8080`.

## Ворота этапов

Ворота — это проверяемое состояние, а не «агент разрешил». Если пункт ворот нельзя показать файлом, страницей или скриншотом, этап не закрыт.
Возврат на шаг назад — нормальный ход, а не провал: если на этапе 13 выяснилось, что у страницы нет состояния ошибки, правится карта на 07, а не дорисовывается состояние на месте.

## Сквозные артефакты

- `docs/brief.md` — источник требований. Меняется только через `02`.
- `docs/spec.md` — ТЗ: функции, приоритеты, критерии приёмки. Меняется через `06`.
- `docs/ds/foundation.md` + `theme.json` — единственный источник цветов, шрифтов, отступов. Контракт: `.claude/rules/wp-theme.md`.
- `docs/ds/components.md` — каталог паттернов/блоков: назначение, анатомия, варианты, состояния, где используется.
- `docs/spec.md` + `docs/features.md` — функции с ID `F-NN`, user stories `US-NN`, критерии приёмки. По ним принимают работу 13, 14, 15.
- `docs/ds/screens/` — карта композиции каждой страницы и индекс `_index.md`.
- `docs/DECISIONS.md` — журнал решений: Решено (`D1` · решение · причина · дата), Предлагаю (`P1` · что · почему · ждёт ответа), Открыто (`O1` · вопрос · что мешает ответить). Ведут все этапы; решённое переезжает из «Предлагаю» в «Решено» с датой, а не переписывается на месте.
- `docs/VOICE.md` — словарь интерфейса: одно понятие называется одним словом на всех страницах. Ведут этапы 10, 11, 12, 13, 14, 16; тексты кнопок, заголовков, пустых состояний берутся оттуда, а не придумываются заново.
- `PROJECT.md` — состояние среды: репозиторий, хостинг, живой URL, счётчик Метрики. Без секретов.
- `.tmp/` — черновики и промежуточные отчёты, можно удалять.

## Единый скелет директивы

Каждая директива 03–19 имеет разделы в этом порядке: **Задача** · **Когда применять** · **Предусловие** (какие файлы должны существовать; если нет — куда отправить) · **Роль** · **Ключевой принцип** · **Граница** (что директива НЕ делает) · **Фазы** (нумерованные, с точками апрува) · **Формат результата** (точные пути) · **Self-check** · **Финал** (что вывести пользователю, в код-блоке) · **Грабли** · **Правила**. Раздел **Self-check** формулируется как проверяемое состояние и совпадает с воротами этапа из таблицы выше.

## Общие правила конвейера

1. **Сначала текст, потом код.** Структура страницы, паттерна, токенов сначала описывается в Markdown и утверждается; правка md в разы дешевле переверстки.
2. **Проверка по факту.** После любой записи в тему/плагин — `php -l` (хук), `curl` страницы, `debug.log`, при визуальных изменениях — скриншот `python scripts/screenshot.py <url>`. «Я написал файл» — не результат.
3. **Никакого хардкода.** Цвета, размеры, отступы — только токены `theme.json`. Прибитый hex или px вне шкалы — баг, который ловит `15`.
4. **Паттерн вместо копипасты.** 3+ повторения разметки → паттерн; 2 — спросить; 1 — локальная композиция.
5. **Состояния обязательны.** Список: данные / пусто / загрузка / ошибка / переполнение. Форма: по умолчанию / ошибки полей / отправка / успех / ошибка отправки. Happy-path-only — не принимается.
6. **Имена — латиницей, контент — по-русски.** Slug'и, имена паттернов, токенов, CSS-классов на английском в kebab-case; тексты интерфейса и документов на русском, с «ёлочками» и буквой ё.
7. **Апрув через `AskUserQuestion`,** не более 3–4 вопросов за раз, с рекомендацией. «Решай сам» = допущение, записанное в артефакт.
8. **Read-only по умолчанию** для аудитов и сканирований. Изменения — только с флагом `--fix` и явным апрувом каждого фикса.
9. **Секреты транзиентны:** пароли хостинга, токены — не в файлы, не в git, не в `PROJECT.md`.
10. **Повторный запуск = синхронизация,** а не пересоздание: директива читает, что уже есть, и дописывает/обновляет.
11. **Решение принимается до вёрстки, а не в собранной странице.** Нет апрува заказчика — нет вёрстки. Лист решений (Сейчас / Предлагаю / Рынок) собирает навык `decision-board` и публикует через `Artifact` для просмотра; апрув заказчик даёт в чате, ответ записывается в карточку страницы. Правка листа стоит минуты, правка собранной страницы — день.
12. **Разбор идёт по классу.** Заказчик показал одну ошибку — сформулируй класс ошибки, заведи правило со способом проверки и почини все места этого класса, а не то, куда показали пальцем. Правило без способа проверки — это пожелание.
13. **Проверка глазами.** Ноль замечаний автоматики не значит, что страница хорошая: читаются ли подписи, не слиплись ли группы, видно ли, что кликается, что происходит с длинным текстом и пустым списком. Чеклист живёт в карточке страницы `docs/ds/screens/<page>.md` и дополняется после каждого разбора.
14. **Возможности проверяются прогоном.** Нетривиальную вещь — поведение rewrite-правил, meta в REST, `meta_query` на SQLite, поведение блочного шаблона — сначала маленькая проба, потом логика. Документация и статьи врут.
15. **Партия, а не всё сразу.** Страницы собираются партиями по одному потоку: весь каталог, потом карточка, потом статейные форматы. Показ партии — с разницей «было и стало» и списком изменений, а не списком файлов.

## Инструменты среды

| Задача | Инструмент |
|---|---|
| Сервер | `scripts/start.ps1 -Background`, `scripts/stop.ps1`, http://localhost:8080 |
| WP-CLI | `tools/wp.cmd --path=wordpress <cmd>` |
| Скриншоты страниц | `python scripts/screenshot.py <url> [--width 1440|375]` (Playwright, ставится в `08`) |
| Исследование | `WebSearch`, `WebFetch`, субагенты `general-purpose`; референсы экранов — MCP `mobbin` |

| Публикация документов заказчику | инструмент `Artifact` (по запросу) |

| Подключения MCP | подключать только то, чем пользуешься на текущем этапе: лишние подключения — это описания инструментов, которые агент читает при каждом запросе, и тем хуже выбирает нужное |
| Figma MCP | опционально, только если заказчик попросит визуальный макет; не в основном пути |
