# DesignStack — сайт-сборник полезных материалов для UX/UI/продуктовых дизайнеров (WordPress)

Цель: лучший ресурс в своей нише. Бриф утверждён 10.09.2026 — `docs/brief.md` (версия 1.1) является источником требований; изменения требований — через `/briefing`, а не молча в коде.

@01_principles.md

## Стек и среда (локально, без Docker/MySQL)

- WordPress 7.1 в `wordpress/`, PHP 8.3 портативный в `tools/php/`, БД — SQLite (`wordpress/wp-content/database/.ht.sqlite`, drop-in `wp-content/db.php`).
- Сервер: встроенный `php -S` с роутером `tools/router.php` → http://localhost:8080 , админка `/wp-admin` (логин/пароль в `.env`).
- WP-CLI 2.12: `tools/wp.cmd --path=wordpress <cmd>`. Локаль сайта ru_RU, ЧПУ `/%postname%/`.
- Живой сайт: https://designstack.ru на Beget (PHP 8.3, MySQL 8.4), SSH-алиас `designstack`, WP-CLI там — `php8.3 /usr/local/bin/wp-cli.phar`.
- Node 24 / npm 11 доступны для `@wordpress/scripts`, Python 3.12 — для скриптов в `scripts/`.

## Команды

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Background   # запустить сервер
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1                # остановить
tools/wp.cmd --path=wordpress theme list                                            # WP-CLI
python scripts/reset.py                                                             # снести БД и переустановить сайт
python scripts/setup.py                                                             # поднять среду с нуля (PHP, WP, WP-CLI)
tail -20 wordpress/wp-content/debug.log                                             # ошибки PHP/WP
```

## Структура

- `wordpress/wp-content/themes/designstack/` — наша тема (единственное место для кода сайта, навык `wp-theme`).
- `wordpress/wp-content/plugins/designstack-*/` — наши плагины. Остальное в `wordpress/` не трогаем и не коммитим.
- `scripts/` — детерминированные скрипты (setup/reset/start/stop, проверки, хуки в `scripts/hooks/`).
- `tools/` — PHP, WP-CLI, роутер (в git не попадают, восстанавливаются `scripts/setup.py`).
- `.claude/skills/` — навыки, `.claude/agents/` — субагенты, `.claude/rules/` — правила с привязкой к папкам.
- `00_pipeline.md` — карта девятнадцати этапов, их ворота и состояние. Директивы, из которых выросли навыки, — в `_archive/directives_v2/`.
- `docs/` — бриф, ТЗ, дизайн-система, аналитика, контент. `docs/DECISIONS.md` — журнал решений (Решено / Предлагаю / Открыто), `docs/VOICE.md` — словарь интерфейса.
- `.tmp/` — временные файлы, `.env` — секреты (не читать вообще).

## Рабочий процесс

1. Перед правками убедись, что сервер запущен (`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/` → 200).
2. Код только в своей теме/плагине. Контент и настройки — через WP-CLI, а не руками в админке (воспроизводимо).
3. После каждой правки: хук сам прогонит `php -l`; ты — проверь страницу `curl`-ом и `debug.log`.
4. БД SQLite: `wp db *` не работает; MySQL-специфичный SQL не писать.
5. Сайт живой: правка контента идёт сразу в двух местах — локально и на хостинге (навык `live-sync`), иначе базы разойдутся.
6. Перед вёрсткой страницы — лист решений и апрув заказчика в чате (навык `decision-board`): нет апрува — нет вёрстки. Тексты интерфейса берутся из `docs/VOICE.md`, решения — в `docs/DECISIONS.md`.
7. Коммитить только по просьбе. В git попадают: тема, плагины `designstack-*`, `scripts/`, `docs/`, `.claude/`, `CLAUDE.md`, `00_pipeline.md`, `_archive/`.

## Как работаем с заказчиком

- Идём этапами. Этап начинается по её слову, следующий сам не начинаю; в конце — одна строка «дальше предлагаю …».
- Апрув — в чате через `AskUserQuestion`, рекомендация первым вариантом (D47). Визуальное она смотрит глазами: варианты живыми образцами на листе (D49).
- Короткий ответ — «давай», «делай», «дальше», «отметила», иногда латинской раскладкой — значит «продолжай». Переспрашивать не надо.
- Факт, сказанный один раз (домен, имя, почта, решение), записывается в `PROJECT.md`, `docs/DECISIONS.md` или память и больше не переспрашивается.
- Её действия в браузере и панели хостинга — по одному шагу за сообщение: куда зайти, что нажать, что прислать назад.
- Работа дольше нескольких минут — промежуточная строка о том, что происходит, а не молчание.
- Пароли, коды и токены не попадают ни в файлы, ни в ответы; `.env` не читаем. Имя автора берётся только с её слов.

## Известные особенности

- Обе машины проекта выходят в сеть **из Казахстана**. Всё, что на сайте заявлено «для России» — доступ, цена, оплата, — проверяется только с сервера или через туннель (навык `ru-check`).
- `winget install PHP.PHP.8.3` ломается (404), поэтому PHP качается напрямую с windows.php.net в `scripts/setup.py`.
- WSL/Docker на машине нет; если понадобится MySQL-совместимость, ставить Docker Desktop отдельно.
- Команды хуков в `.claude/settings.json` пишутся только с абсолютным путём: рабочая папка агента и субагентов плавает, относительный путь молча ломает хук.
- Длинные тексты и скрипты пишутся инструментом записи файла, а не heredoc: heredoc около 13 КБ или с апострофом падает и не пишет ничего.
